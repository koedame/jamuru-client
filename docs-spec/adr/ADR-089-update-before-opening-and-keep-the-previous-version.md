# ADR-089: 起動のたびに本体を開く前に更新し、入れた版が起動するまで前の版を残す

## Status

Accepted。[ADR-041](./ADR-041-self-update.md) の「起動の 20 秒後と 6 時間おきに確かめる」を、起動したら本体の画面を開く前に確かめて入れる形に変える。署名の検証、取得先、上限時間、1 度に 1 つ、セッション中は入れない（[ADR-082](./ADR-082-check-and-install-updates-by-hand.md) を含む）は変えない。

## Context

自動更新（ADR-041）は、アプリが開いてから 20 秒後に新しい版を探して入れ、再起動していた。次の 2 つが問題だった。

- **開いたあとに入れ替わる。** 起動して接続の画面を見ているうちに、何も言わずに再起動する。古い版のまま 20 秒の間に入室すると、今度はセッションを抜けるまで入らない。
- **入れた版が起動しなければ、戻る手段が無い。** 更新はインストール先の本体を置き換える。新しい版がその端末で動かない・起動中に落ちる・画面が出る前に固まる、のどれでも、アプリは無くなり、起動し直しても同じ版がまた失敗する。マイコンのファームウェアの更新が A 面・B 面を持つのは、この状態を作らないためである。

## Decision

### 1. 起動したら、本体を開く前に更新する

自分で入れ替えられる配布形態（AppImage・macOS の `.app`・Windows の NSIS）のリリースのビルドは、起動するとまず新しい版を確かめ、あれば入れて再起動する。本体（メインのウィンドウ・接続・背景の更新・遠隔デバッグ）は、その結果を待ってから開く。

1. 新しい版を確かめる（上限 10 秒）。無ければ、または確かめられなければ、そのまま本体を開く
2. 見つかれば、ダウンロードし（上限 3 分）、入れて、入れた版で起動し直す
3. ダウンロードか入れ替えに失敗すれば、何もせず本体を開く（前の版のまま）

- **確かめる・入れる条件は、背景の更新と同じ。** `auto_update` がオン、利用規約に同意済み、リンク（`jamuru://join/…`）から起動したのではない。どれかに当たれば、確かめずに本体を開く。リンクで起動した人は入室しようとしているので待たせない。確かめている途中に届いたリンクも同じ扱いで、更新を打ち切って本体を開く。
- **小さな窓で進み具合を出す。** 確かめるのに 1 秒より長くかかったとき、または新しい版が見つかったときだけ出す（ふだんの起動では何も出さずに開く）。「アップデートを確認しています」「新しい版をダウンロードしています（○%）」「新しい版を入れています」「再起動しています」と、「待たずに開く」。
  - 「待たずに開く」と窓を閉じることは、確かめている間とダウンロードの間だけ効く。入れ替えを始めたら、途中で止めると本体が半分のまま残るので、終わるまで待つ。
- **起動のときに確かめたら、背景の更新の最初の確認は 6 時間後。** 確かめていなければ（リンクで起動した、待たずに開いた等）これまでどおり 20 秒後。

却下: 本体を開いてから裏で入れ、次の起動で切り替える。入れ替えは本体を置き換えるので、動いている本体の下で入れると次の起動まで壊れた状態が残る OS がある（Windows の NSIS は動いているアプリを終わらせてから入れる）。

### 2. 入れる前の版を残し、入れた版が起動するまで見届ける

入れる前に、インストールされているものをそのまま写して脇に置き（スロット）、見届け役を立ててから入れる。入れた版が起動したと言えば残し、言えなければ写しを戻して前の版を起動し直す。

- **写すもの。** Linux は AppImage のファイル、macOS は `.app` の束、Windows はインストール先のうち本体のファイル（同じ場所にあるアプリのデータは除く）。写しはディスクに書き切ってから入れる。写せない形（AppImage でない Linux・書き込めない場所に置いた本体・本体そのものにアプリが書き込めない形）は、前の版を残せないので自分では入れず、新しい版を知らせるだけにする（[ADR-076](./ADR-076-notify-newer-release-to-packages-that-cannot-self-update.md) の扱い）。管理者が入れた `.app` は、更新の部品が管理者のパスワードを求めて入れ替えるが、見届け役にはそのパスワードが無く戻せないので、ここに当たる。
- **見届け役は、前の版のプログラムを写しから動かしたもの。** 新しい版がその端末で動かなくても、前の版は動く。窓も音もネットワークも持たず、決まるまでのあいだだけ生きる。Windows では名前を変えた写し（`jamuru-update.exe`）で動かす。インストーラーがアプリの名前のプロセスを全部終わらせるため。見届け役が立ったと数えるのは、そのロックを持って見届けを始めたと書いてから（30 秒まで待つ）。プロセスが作れても動けない写しで入れ替えを始めないため。
- **誰が生きているかはファイルのロックで見る。** 前の版・新しい版・見届け役がそれぞれロックを持ち、プロセスがどう終わっても OS がロックを放す。プロセス ID は別のプログラムに使い回されるので頼らない。
- **決まるのは見届けごとに 1 度だけ。** 「残す」「戻す」「やめる」のどれかを、先に書いた方が決める（見届けごとの名前のファイルの作成で、後から来た方は失敗する）。新しい版が「起動した」と言うのと、見届け役が「起動しなかった」と諦めるのが同時でも、片方だけが通る。決まって閉じた見届けを、遅れて来た者（閉じたあとで諦めた見届け役など）が決め直すことはない。決めたあとで、その見届けがまだ開いているかを確かめ、閉じていれば書いたものを消して何もしない。新しい版の 2 つ目の起動がロックを待っていたあいだに決まっていれば、その起動は見届けに加わらず、決まったことに従う。
- **「起動した」の意味。** メインのウィンドウに最初の画面（利用規約の同意画面か、接続の画面）が描けて、そのあと 10 秒落ちずに動いたこと。画面の描画に失敗したとき・規約を読めなかったときは言わない。規約の改定で同意画面になった版は、同意を待たずに「起動した」に数える（読んでいる間に戻されないように）。
- **見届け役が諦める時間。** 前の版が後を託してから新しい版が立つまで 60 秒（Windows はインストーラーがその間に入れるので 180 秒）、新しい版が立ってから「起動した」と言うまで 180 秒。新しい版が消えたら 10 秒待って（自分で再起動する版は、その間にまたロックを取る）落ちたとみなす。
- **戻すとき。** 新しい版が動いていれば終わらせ、写しを元の場所に戻し、前の版を起動し直す。人が新しい版を「起動した」前に閉じたときは、戻すが起動はしない（閉じた人の意図を守る）。
- **戻した版は、自分では入れ直さない。** 戻した版は覚えておき（8 つまで）、起動のときも背景の更新でも自分では入れない。設定の「更新して再起動」で人が頼んだときは入れる（新しい版で直っていることがある）。自分で入れようとした版も、入れ替えに失敗したときを含めて 24 時間は自分では入れ直さない。同じ版が起動 → 入れ替え → 起動の輪になるのを、記録が壊れたときにも止めるため。見届けの途中には、次の版をダウンロードもしない。
- **「起動した」と言わない版は 3 回まで。** 新しい版が「起動した」と言わないまま 3 回起動したら、次の起動ではもう試さず、前の版へ戻す。人が閉じたあとの起動し直し（同意画面からの再起動など）は数えない。見届け役が立てられない端末でも、落ちる版を起動のたびに試し続けないため。

### 3. 途中で何が起きても、次の起動で正しい状態に戻る

| 起きたこと | 次に起きること |
|---|---|
| 入れ替えの最中に前の版が落ちた | 見届け役が写しを戻して起動し直す |
| 入れ替えが失敗した | 前の版のまま。Linux と macOS は写しを戻してから見届けを閉じる。Windows はインストーラーがアプリの終了後に動くので、起動できなかったときは本体に触れておらず、戻さない（動いている本体に上書きしない） |
| 入れ替えが終わったが、再起動の前に前の版が終わった | 次の起動が新しい版で、そこから見届けを始める |
| 前の版が後を譲ったあとで、前の版が起動した（インストーラーが途中で終わった。端末の再起動で見届け役も消えていた） | その起動はすぐ終わり、見届け役を立て直す。見届け役はインストーラーの時間（Windows は 180 秒）を待ってから写しを戻し、前の版を起動する |
| 見届け役が消えた（端末の再起動） | 新しい版の次の起動が見届け役を立て直す。立てられなければ、「起動した」と言わないまま 3 回起動したところで前の版へ戻す（戻す者がいなければ新しい版のまま開く） |
| 決まって閉じたあとに、遅れて来た者が決めようとした | 何も起きない（決まったことは見届けごとで、閉じた見届けには書けない） |
| 写しを戻せない | 3 回まで試し、それでも戻せなければ見届けをやめてアプリを起動する（起動できないまま固まらない） |
| 見届けの記録が壊れている・知らない形 | 捨てる（知らない形は、後の版のものなので触らない） |
| 前の版を戻している最中に人がアプリを起動した | その起動はすぐ終わり、戻し終えた見届け役が前の版を起動する |

### 4. 配る前に、実際の配布物で訓練する

リリースのワークフローは、各 OS（Linux の AppImage・macOS の `.app`・Windows の NSIS）で更新の訓練（`scripts/update-drill.py`）が通るまで何も公開しない。この版のソースから 0.0.1 と 0.0.2 の 2 つを訓練用の鍵でビルドし、0.0.1 を入れて 0.0.2 を新しい版として手元で配り、次を確かめる。

- 0.0.2 が起動すると、残される（入っているのが 0.0.2 で、写しが消えている）。画面まで出て、そのあとも動き続ける
- 0.0.2 が起動してすぐ落ちる・固まる・そもそも動かない・画面が出たあと「起動した」と言う前に落ちる、のどれでも、0.0.1 の本体の束がファイルの中身と権限まで元どおりに戻って起動し、最初の画面まで出て動き続け、0.0.2 を覚えて入れ直さない
- Linux では、利用者の端末と同じく AppImage を FUSE でマウントして動かす

訓練用のビルドだけが、環境変数で自分をわざと壊せる（`update-drill` 機能）。リリースとベータのビルドにこの機能が無いことを、リリースのワークフローがバイナリで確かめる。

却下: 本物の署名鍵で壊れた版を作る。壊れた版が本物の鍵で署名されて残ることになる。訓練用の鍵は訓練のたびに作って捨てる。

## Consequences

- 起動のたびに、本体を開く前に GitHub（更新情報の取得先）に 1 回問い合わせる（ADR-041 の通信が、起動の 20 秒後から起動時に移る）。送るのはこれまでどおりアプリの版と OS の種類だけ。新しい版が無ければ、ふだんの起動は確かめる時間だけ遅れる（上限 10 秒。届かないネットワークでは最大で 10 秒待ってから開く）。
- 見届けの記録はアプリのデータの場所の `update/` に置き、`watch.log` に見届け役のしたことを書く（端末の中だけで、どこにも送らない）。写しは見届けが終わると消える。入れ替えのあいだは、本体がもう 1 つ分の場所を使う。
- 「起動した」は画面が描けて 10 秒動いたことまでで、その先の不具合（音が出ない・接続できない）では戻らない。そういう版は、次の版か、ベータ用の置き場を戻す操作（[ADR-057](./ADR-057-beta-channel-rollback.md)）で直す。
- 写し・見届けの記録・「入れ終えた」「後を譲った」の印はディスクに書き切ってから次へ進む（電源が切れても残る）。見届けのあいだのプロセスどうしの合図（起動した・閉じた・何回目か）は書き切らない。電源が切れれば見届けは合図の前に戻り、その状態から続く。
- 受け入れた穴:
  - 入れ替えの最中に電源が切れ、本体が起動できない形で残る（Linux の更新の部品は AppImage を書き切らずに置き換える。Windows のインストーラーが本体のプログラムを消したところで止まる）と、見届け役も消えているので起動するものが無く、戻らない。ログインのときに見届け役を立て直す仕組みで塞げるが、OS に常駐の項目を足すことになるので、別に決める
  - この版へ上がる最初の更新は、前の版の更新の仕組みが入れるので、見届けが無い。この版からあとの更新が見届けられる
  - 訓練は、この版のソースから作った 2 つの版で行う。前のリリースからこの版へ上がる経路は通さない。訓練のビルドは署名・公証をしておらず、macOS では `/Applications` ではなく一時フォルダーに置く
  - Windows でインストーラーが途中で終わり、前の版が起動されたときは、見届け役がインストーラーの時間（180 秒）を待ってから戻すので、その間アプリが開かない
  - 入れ替えと再起動のあいだに届いたリンクは失われる（入れ直したあとにもう一度開く）
  - macOS では、写した `.app` を LaunchServices が一時的に覚えることがある（見届けが終わると写しは消える）
  - Windows で、インストーラーが 180 秒を超えて動き続けていると、その下で写しを戻すことになる
- メインのウィンドウは Tauri に作らせず（`create: false`）、起動の更新のあとでアプリが作る。
