# ADR-037: 利用状況の送信は、利用者が設定でオンにしたときだけ行う

## Status

Accepted。決定 2 の「送らない」と決定 4・5 の「外す 5 項目」は、[ADR-042](./ADR-042-usage-reporting-includes-investigation-data.md) で変わった（デバイス ID・自前サーバーの URL・自分の IP アドレスは送る。外すのは表示名と部屋の履歴の 2 項目。デバイス ID は設定でなく `audio_env` で送る）。

## Context

特定の機材（オーディオインターフェース）・OS・回線で起きる不具合は、利用者の報告を待つだけでは見つけにくい。アプリが動いた様子（環境・設定・エラー・セッションの集計）が分かれば、どの版のどの環境で何が起きているかを数えられる。

一方で、jamjam は会員登録を持たず（[ADR-024](./ADR-024-device-identity-instead-of-accounts.md)）、利用者は何が外に出るのかを知らずに使い始める。送る内容には、デバイスの名前のように、利用者自身の名前が入りうるものもある。

## Decision

1. **既定はオフ。初回起動でも、既存の利用者にも、確認のダイアログは出さない。** 設定の Diagnostics タブの「利用状況を送る」を、利用者が自分でオンにしたときだけ動く。オンにするまで、何も集めず、何も送らず、インストール ID も作らない。
   - 却下: 初回起動のダイアログで選ばせる。最初の起動で、何のことか分からないまま押させることになる。
2. **説明文に、何のために送るかと、何を送るかを書く**（英語・日本語）。オンにする動機は、この説明文にしかない。
   - 送る: アプリの版・OS・CPU とメモリ・音声デバイスの名前と対応・設定・セッションごとの集計（継続時間・遅延・パケットロス）・エラーの種別・クラッシュの位置。
   - 送らない: 表示名・部屋の履歴・自前サーバーの URL・デバイス ID・端末識別子・音声・チャット。
   - 音声デバイスの名前は OS が返すとおりに送る。「太郎の AirPods」のように利用者自身の名前が入りうるので、説明文でそのことに触れる。
3. **「送る内容を見る」で、次に送る NDJSON をそのまま表示する。** インストール ID も含める。何が出ていくかを、利用者が実際の文字列で確かめられる。
4. **設定は丸ごと送り、外すのは 5 項目だけ**: `peer_name` / `connection_history` / `server_url` / `input_device_id` / `output_device_id`。項目ごとの許可リストは持たない（項目が増えたときに、送る側の一覧の更新を忘れて診断に必要な設定が欠けるのを避けるため）。端末識別子（`device_identity.json`）と設定ファイルのパスも送らない。
5. **設定に URL・ID・名前・パスの類を足すときは、外す側（`src/telemetry/settings.rs` の `LEFT_OUT`）に入れる。**
6. **止め方は、スイッチをオフにすること。** オフにすると、未送信のイベント・開いているセッション・インストール ID・送っていないクラッシュの記録を捨てる。オンにし直すと別のインストール ID になる。
7. 収集と送信は `jamjam.log`（[ADR-036](./ADR-036-diagnostic-log-file.md)）とは別の経路にする。同意していないログが外に出る道を作らない。

## Consequences

- オンにする利用者は一部に限られる。集めた値は、全利用者の代表としては読めない。
- 設定に新しい項目を足した人が、外すべきかを考えないと、その項目は送られる。歯止めは、外す 5 項目が出力に無いことを確かめるテストと、「送る内容を見る」と、上の 5 のルールである。
- デバイスの名前に利用者の名前が入る場合、インストール ID と結びつく。説明文と「送る内容を見る」で利用者が知ったうえでオンにする。オフにすれば ID も捨てる。
- 送信の中身と項目の定義は [api/telemetry.md](../api/telemetry.md) と `src/telemetry/schema.json`、要求は REQ-TEL。
