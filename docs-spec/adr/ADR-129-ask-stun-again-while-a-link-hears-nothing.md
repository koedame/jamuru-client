# ADR-129: 受信が無いリンクがあるあいだ、音声のソケットで STUN を引き直し、知らせていなかったアドレスを部屋に知らせる

## Status

Accepted

## Context

Room check（[ADR-117](./ADR-117-check-many-peers-on-hosted-runners.md)）で、アプリを使わない UDP の確認では通る組が、アプリでは受信 0 のままになる。
[ADR-119](./ADR-119-send-in-turns-after-a-quiet.md) は「両端が黙って、順番に先に送り直す」で一部を解いた。ADR-119 が次の手として残したのが、受信が無いリンクの STUN のやり直しと、新しいポートの公開（`UpdatePeerInfo`）だった。

入室のときに音声のソケットで STUN を引いて公開した外のポートは、その後に NAT が割り当て直すと（NAT の機器が再起動した、流れが表から消えた、別のアドレスへ付け替わった）、実際に出ていくポートと食い違う。
相手は公開された古いポートへ送り続け、こちらの送出は相手の NAT に届かない。両端は送り続けても、どちらも受信が 0 のまま変わらない。

Linux の NAT 2 台（`tests/nat/run.sh`）で確かめたこと:

- 入室後に片側の NAT が外のポートを付け替えると（`moved-a`・`moved-b`）、STUN を引き直さない版は両端とも受信 0 のまま。引き直す版は、最初の問い合わせの 6 秒後に新しいポートを知らせ、相手が張り直して、両端が受信する。
- 両側の NAT が、こちらの側から送るより前に届いた通信を覚える形（`record-both-*`）は、この方法では解けない。覚えた組と重なって別の外のポートに付け替えられた流れは、STUN の流れ（別のあて先）からは見えず、STUN が返すポートは公開したものと同じままだった。conntrack を見ると、相手との流れの外のポートは STUN が見るものと違った。

## Decision

- **音声のソケット `UdpMux` が STUN の答えを受け取る。** ソケットを読むのは `UdpMux` だけなので、STUN の結果パケットを読み取りの中で（リンクの振り分けの前に）取り、聞いたあて先からの答えだけを受け付ける。別のソケットから引くと、返るポートが音声のものと違う（[ADR-035](./ADR-035-stun-through-the-audio-socket.md)）
- **引き直すのは、受信が 1 つも無いリンクがあるとき**だけ。そのリンクが開いてから 6 秒後に 1 回、そのあと 30 秒ごとに、最大 4 回。全部のリンクが聞こえているあいだは引かない。聞こえている音声の経路・送出・遅延には何も足さない（STUN の問い合わせは数十バイトのパケット数個）
- **「受信が 1 つも無い」は、リンクの状態に関係なく見る。** 確認に答えが無くても「つながった」ことにして経路を推測する場合、アプリは 2 秒の無音で再接続中、さらに 10 秒で失敗と扱う。状態が「開始中」のリンクだけを数えると、Room check の実機（macOS）のようにすぐ再接続中になるリンクで一度も引かれなかった（引いた回数 0 を報告に足して分かった）
- **知らせていないアドレスを見たら、`UpdatePeerInfo` で新しい候補の一覧を知らせる。** 新しいアドレスを先頭にし、知らせていた候補は残す（相手が古いアドレスにまだ届くことがあるため）。STUN で見たアドレスは最大 3 つまで、古いほうから落とす。ポート開放（port_mapped）の候補は落とさない
- **張り直しは名簿が行う。** 相手の候補の一覧が変わり、リンクが聞こえていないとき、名簿はそのリンクを終えて新しい候補で開き直す（REQ-CON-134）。新しい仕組みは足さない
- 中継（TURN 相当）は作らない
- 検討して採らなかったもの
  - ソケットごと作り直して引き直す: 開いているリンクが全部切れる
  - 定期的に引く: 聞こえているリンクのあいだは要らない問い合わせになる

## Consequences

- 解けるのは「公開したあとに外のポートが変わった」形。両側が覚える形（上の `record-both-*`）は解けず、Room check で受信が 0 の組が残りうる。解くには、別の手（ADR-119 で試した、先に送る側を決める順番では抜けない）が要る
- STUN を引き直しても外のポートが変わっていなければ、何も知らせず、名簿は何もしない
- 受信が無いリンクがあるとき、最大 4 回の STUN の問い合わせ（IPv4 のサーバーへ数パケット）が、そのリンクのあいだだけ出る
