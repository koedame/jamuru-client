# ADR-040: 入力・出力チャンネルの設定は、デバイスを開くチャンネル数と、取り出す・置く番号を決める

## Status

Accepted

## Context

設定の「入力チャンネル」「出力チャンネル」（`input_channel_l` / `input_channel_r` / `output_channel_l` / `output_channel_r`。多チャンネルのインターフェースの何番を使うか）は保存されるだけで、音には届いていなかった。キャプチャはデバイスの先頭の 1〜2 チャンネルで開かれ、再生は先頭の 2 チャンネルに書かれていた（[ADR-038](./ADR-038-transmit-channels-select-capture.md) が入力側を「別の欠陥として残っている」と記録した）。8 チャンネルの仮想デバイス（PipeWire の null sink）を使う GUI E2E が、5・6 番を選んでも 5 番の音がメーターに出ず、1 番の音が出ることと、受信音が 5・6 番でなく 1・2 番に出ることを再現した。

## Decision

1. **デバイスは、選んだ番号に届く最小のチャンネル数で開く。** デバイスが申告するチャンネル数のうち、選んだ最大の番号（1 始まり）以上で最小のものを使う（`smallest_channel_count`）。申告が読めないデバイスには、必要な数をそのまま求めて、断るかどうかをデバイスに任せる。
2. **入力は、開いたデバイスのフレームから選んだチャンネルだけを取り出して、後段に渡す。** 後段（リング・メーター・ローカルモニタリング・送信）は、従来どおり 1 または 2 チャンネルのフレームだけを見る。線路の形式・パケットの大きさ・数は変わらない。送信チャンネルがステレオで右が未設定なら、左を両側に送る。
3. **出力は、線路のステレオを、選んだチャンネルに置いて、他のチャンネルは無音にする。** ローカルモニタリングは置く前のステレオに混ざるので、選んだ出力から聞こえる。右が未設定（1 チャンネルの出力）なら、左右を平均して左に置く。
4. **既定（入力 1・2、出力 1・2）は従来と同じ動きにする。** 2 チャンネルのデバイスをそのまま通し、コピーも挟まない。
5. **選んだチャンネルを持たないデバイス（多チャンネルのインターフェースからノート PC のマイクに替えた、など）では、先頭のチャンネルにする。** 入力は選択 → 先頭の同じ幅 → 先頭 1 チャンネルの順に、出力は選択 → 先頭 2 チャンネルの順に試し、失敗を警告としてログに残す。古い設定が入力も音も無い状態を作らない（ADR-038 の 2 → 1 の落とし直しと同じ考え方）。
6. **接続中に設定を変えたら、その場で反映する。** 入力はキャプチャを開き直し（ADR-038 の送信チャンネルと同じ）、出力は同じプレイアウトバッファのまま再生を開き直す（デバイス切り替えと同じ）。

## Consequences

- REQ-AUD-118/119 の検証は、選び方・置き方の純粋な関数と、広いデバイスに置く再生の経路をユニットテストで、実デバイスを開いて音が届くことを、8 チャンネルの仮想デバイスを使う GUI E2E で確かめる。
- 仮想デバイスで測れるのは「多チャンネルで開いて、選んだ番号を読む・書く」まで。ドライバごとのチャンネル数の申告、ASIO / CoreAudio のチャンネルの並び、物理入力、往復の遅延は実機でしか測れない（`Plans.md`「実環境待ち」）。
- ALSA の pipewire プラグインは、デバイスの実際のチャンネル数と無関係に 1〜64 チャンネルを申告するので、Linux の仮想デバイスでは 5. の落とし直しは起きない（本物の ALSA デバイスや CoreAudio / WASAPI では、選んだ番号に届く設定が無ければ開けず、落とし直しに入る）。
