# ADR-081: メニューバーは OS ごとの作法に合わせて作り、状態に応じて項目を有効・無効にする

## Status

Accepted

## Context

アプリには自前のメニューが無かった。macOS では Tauri が付ける既定のメニューが出ていた（英語固定で、アプリの言語設定に追従せず、ヘルプの中身は空）。Windows と Linux にはメニューバー自体が無かった。「このアプリについて」「使い方」「問題を報告」などの入口は、設定ウィンドウの中のタブにしか無い。

OS ごとにメニューの作法が違う。

- **macOS**: 画面の最上部に、全ウィンドウ共通のメニューが 1 つ。アプリ名のメニューに「このアプリについて」「設定…」「終了」を置く。Edit メニューが無いと、WebView の入力欄でコピーと貼り付けが効かない。ヘルプメニューには検索欄が自動で付き、ヘルプを充実させることが期待される。
- **Windows / Linux**: ウィンドウごとにメニューバーがあり、設定は「ファイル」に、「このアプリについて」は「ヘルプ」に置く。

## Decision

1. **メニューバーを全 OS に出す。** Windows / Linux にも標準のメニューバーを出す（出さない案は、このアプリ固有の入口が設定の中だけに残り、macOS だけ作り込むことになるので却下）。
2. **構成は OS の作法に合わせる。** macOS はアプリ名・ファイル・編集・表示・ウィンドウ・ヘルプ。Windows / Linux はファイル・編集・ヘルプ（設定と終了はファイル、「jamuru について」はヘルプの末尾）。Windows / Linux は OS が持たない項目（フルスクリーン・やり直しなど）を作らない。終了は Linux の OS 標準項目が無いので自前の項目にする。
3. **ヘルプを充実させる。** 使い方、うまくいかないとき（どちらもブラウザで docs を開く）、システム診断、ログフォルダを開く、問題を報告、利用規約、プライバシーとセキュリティ、ライセンス、お知らせ。診断・問題報告・規約・ライセンスは、設定ウィンドウの該当タブを直接開く。
4. **項目は状態で有効・無効を切り替え、メニューの形は変えない。** 判断は純粋な関数（`menu.rs` の `Item::enabled`）で、入力は「前面のウィンドウの種類（メイン / 設定 / 手伝い）・規約に同意済みか・ルームに入れる状態か・ルームの中か・テストルームがあるか」。規約に同意するまでは、ネットワークに出る項目・設定の項目を無効にする（REQ-TRM-003）。手伝う側のウィンドウからは、ブラウザとログフォルダの項目だけ使える。メニューは全ウィンドウで 1 つを共有するので（Windows / Linux でも）、前面のウィンドウが変わるたびに切り替える。
5. **言語はアプリの言語設定に追従する。** 設定がなければ OS の言語、それも日本語でなければ英語（画面と同じ順）。OS 標準の項目（切り取り・コピー・終了など）の文言も、自前の表から出す（OS 任せにすると英語になる）。言語が変わったらメニューを作り直し、それ以外の変化では項目の有効・無効だけを変える。`Info.plist` に `CFBundleLocalizations`（en・ja）を足し、macOS が自分で出す文言も日本語になるようにする。
6. **この変更ではショートカットを付けない。** 自前の項目に独自のキーは割り当てず、OS 標準の項目が持つ OS 標準のキー（コピー、終了、ウィンドウを閉じるなど）だけが残る。ショートカットは、アプリ全体の割り当てとして別に精査して決める。仕様書にある `Cmd/Ctrl + M`（ミュート）は macOS 標準の「しまう」と衝突し、`Cmd/Ctrl + 1・2` はミキサーとチャットを別ウィンドウで開く前提で今の画面と合わないので、決めるときに見直す。
7. **画面に作用する項目は、メインウィンドウのイベントで渡す。** ルームの作成・参加・テストルーム・招待コードのコピー・退室・設定依頼は、メインウィンドウの画面が持つ状態を使うので、`menu:action` イベントで画面に頼む。画面は、頼まれた時点でその操作ができる状態かをもう一度確かめる。手伝う側の画面は、これを受け取らない。

## Consequences

- 設定ウィンドウは、開くタブを指定できる（アドレスの `#/settings/<tab>`、開いている窓には `settings:select-tab` イベント）。
- メニューはネイティブで WebView の DOM に無いので、GUI E2E からは押せない。メニューの中身（構成・有効条件・文言・行き先）は純粋な関数と表にして、単体テストで検証する。macOS 実機での見た目の確認は別に行う。
- Windows で「jamuru について」を選ぶと、OS 標準のダイアログ（題名は英語）が出る。
- メニューの項目を足すときは、`menu.rs` の `Item` に足し、`layout` に置き、有効条件とテストを書く。
