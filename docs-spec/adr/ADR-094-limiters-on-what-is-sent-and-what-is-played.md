# ADR-094: 送る音と聞こえる音に、遅延を足さないリミッターを付ける

## Status

Accepted。[ADR-005](./ADR-005-no-audio-processing.md) の「将来のオプションの既定は常に OFF」を、リミッターについてだけ置き換える（下の Decision 2）。

## Context

jamuru には、0 dBFS（デジタルの最大）を超える音を抑えるものが無い。次のとき、音は割れ、耳と機材に危険が及ぶ。

- ハウリング、ケーブルの抜き差し、マイクのゲインの上げすぎ。送る音の音量（最大 200 %）とパンで、入力が 0 dBFS 以下でも送る音は 0 dBFS を超えうる
- 相手が多いルーム。聞こえる音は全員の音の和なので、1 人ずつは 0 dBFS 以下でも、和は超える
- 相手が別のアプリで音量を上げすぎている、など自分では止められない音

超えた音は、いまはデバイスの境界で切り詰められる（ハードクリップ）。競合の SYNCROOM（2.1.9）は、入力と全体の出力にリミッターを足し、それぞれ設定で ON / OFF できる。SyncueSong も、マイクの効果の最後にリミッターを持ち、追加の遅延は無く、先読みのバッファは使わない。

低い遅延と良い音質はどちらも犠牲にしない（AGENTS.md の最優先要件）。

## Decision

1. **リミッターを 2 つ置く。入力用は、送る直前（音量・パン・ミュートの後、デバッグ用の取り出し口の前）。出力用は、全員の音とローカルモニタリングを足した直後（録音出力 `C` と再生の前）。** 録音出力 `A`（自分の音そのまま）と `B`（相手の音そのまま）、ローカルモニタリングに送る音、入力のレベルメーターは通らない。出力側のマスターのレベルメーターは、リミッターの前の値を出す（どれだけ超えているかが分かる）。
2. **既定は両方 ON。** 次の 2 つを満たすので、ADR-005 の「音声処理を行わない」の例外にする。
   - 0 dBFS 以下の音には一切触れない（ビット単位で同じ。REQ-CORE-003 は「0 dBFS 以下のサンプルは」に絞る）。触れるのは、デバイスの境界でいずれ切り詰められる音だけ
   - 遅延を足さない（Decision 3）。

   ADR-005 が避けたのは、ふつうの音量の音まで変える処理（AEC・NS・AGC）と、その遅延。リミッターはどちらにも当たらない。超えたときの音は、ON のほうがハードクリップより歪みが小さい（測定は Consequences）。ON を既定にしない理由が無いので、ADR-005 の「既定は常に OFF」はこの機能には当てはめない。
3. **先読み（lookahead）をしない。** 到着した音が 0 dBFS を超えていれば、その標本のうちにゲインを下げる（アタック 0）。そのあと 100 ms かけて 1.0 に戻す（リリース）。ゲインは 1 フレーム（チャンネルの組）で 1 つで、チャンネルが違っても片方だけが下がって音像が動かない。足す遅延は 0 標本。先読みのリミッターは音が自然だが、先読みの分だけ遅れるので採らない。
   数でない値（NaN）と無限大の標本は、相手のバイト列からそのまま復号されうる。ゲインでは天井に収められない（無限大にゲイン 0 を掛けると NaN）ので、リミッターの中で無音の標本にする。有限の標本には触れない。
4. **天井は 0 dBFS（1.0）。** それ以下の音を変えず、超える音だけを止める。それより低い天井は、ふつうに大きく弾いた音まで変えるので採らない。
5. **設定は 2 つ、「入力リミッター」「出力リミッター」。** 設定の「オーディオ」タブの末尾の「リミッター」の節に、スイッチで置く（保存する。部屋にいれば、部屋を出ずに音声のセッションへすぐ伝える）。設定の手伝い（ADR-044）も同じ設定として扱う。
6. **何回効いたかを、セッションごとに数える**（`audio_quality` の `input_limited_frames`・`output_limited_frames`）。
7. **24-bit で送る形式（ADR-093 の 24-bit 整数）との関係。** 24-bit 整数は ±1.0 を超える音を切り詰める。入力リミッターが ON なら、送る音は 0 dBFS を超えないので、切り詰め（`samples_clipped`）は起きない。入力リミッターを切ると、超えた音は 24-bit の側で切り詰められ、数えられる。
   出力リミッターは、受け取った音を足した後なので、24-bit の切り詰めとは別（相手の送る音が 0 dBFS 以下でも、足した和は超える）。

却下した案:

- 先読みのリミッター: 音は自然だが、先読みの長さだけ遅延が増える。遅延を足す案は `[design]` で聞く決まりで、先読みを使う SyncueSong も「ゼロ」と書いていて、同じ作りにそろえた
- 既定 OFF: 切り替えた人しか守られない。不意の大きな音は、設定を開く前に来る
- 天井を −1 dBFS などにする: 0 dBFS 以下の音まで変わる。REQ-CORE-003 を保てない
- リミッターの代わりに音量を自動で下げる（AGC）: ふつうの音まで変わる

## Consequences

- 超えない音は、そのまま（ビット一致）。遅延は 0 標本で、処理時間は 64 フレームのステレオ 1 コール（1 フレーム 1333 µs）あたり、超えない音で約 0.2 µs、超える音で約 0.3 µs（最適化ビルド。約 0.02 %）。`tests/limiter_measure.rs` で測る
- 超えた音の歪み（440 Hz の正弦波、ゲインが落ち着いた後の、基本波に対する残りの大きさ）:

  | 振幅（0 dBFS = 1.0） | リミッター | ハードクリップ（リミッター無し） |
  |---|---|---|
  | 1.1（+0.8 dB） | −68 dB | −28 dB |
  | 1.5（+3.5 dB） | −55 dB | −16 dB |
  | 2.0（+6 dB） | −49 dB | −13 dB |
  | 4.0（+12 dB） | −40 dB | −9 dB |

  1 回きりの鋭いピークは、その標本で抑えるので、ゲインの段差が 1 つできる。先読みのリミッターより荒いが、ハードクリップよりは小さい
- 入力リミッターを切ると、送る音の 0 dBFS 超えは相手に届く（24-bit では切り詰め）。出力リミッターを切ると、デバイスの境界で切り詰められる
- 遠隔操作（ADR-043）の `settings_change` に 2 つの設定（`input_limiter`・`output_limiter`）が増える。新しいコマンドは無い
- 古い設定ファイルには項目が無いので、読むと両方 ON になる
