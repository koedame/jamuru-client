# ADR-083: 音声のセッションは、ルームに入った時点で始まり、相手がいなくても動き続ける

## Status

Accepted。[ADR-077](./ADR-077-every-participant-is-linked.md) §4「音声のセッションは最初の 1 本で始まり、最後の 1 本が終わると止まる」を置き換える。相手ごとの接続・全員と繋ぐ決め方・1 つの音声ソケットの共有は変えない。

## Context

ルームを作って 1 人でいるとき、入力のレベルメーターが動かなかった。メーターを動かすのは音声のセッションが開いたマイクで、
セッションは最初の相手との接続（`Audio::Start`）で始まっていたので、1 人のあいだはマイクが開かれていなかった。
macOS のマイクの許可を求める表示も、誰かが入ったときに初めて出ていた。

1 人でも、マイクが拾えているかを確かめたい（相手を待つあいだに、入力デバイスの選びや音量が合っているかを見る）。

## Decision

- ルームに入ったら、音声アドレスの公開（`Audio::Advertise`）のあとに `Audio::Open` を実行する。バックエンドの `open_audio` で、デバイスと
  公開したソケットを使うセッションを、相手の接続なしで始める（動いていれば何もしない）。
- 最後の 1 本の相手が退室しても、セッションは止めない。その相手の接続を閉じる（`Audio::End`）だけで、マイクの取り込みと公開したアドレスは
  そのまま続く。以前の `Audio::Stop`・`Audio::Advertise` の組は使わない。
- セッションが止まるのは、退室・シグナリングの切断・デバイスが開けないとき。後の 2 つは、ルームに入り直したとき（`Audio::Open`）か、
  次の相手との接続（`streaming_link`）で、同じ手順で始め直す。
- 相手がいないあいだは、マイクの音をだれにも送らない。メーターとローカルモニタリングが動くだけである。

CLI はプロセスの開始時にセッションを始めてルームをまたいで持ち続けるので、`open_audio` は何もしない。

## Consequences

- 入室の時点でマイクが開く。macOS のマイクの許可の確認は入室時に出る（以前は誰かが入ったとき）。
- 入室のたびにデバイスを開くので、デバイスが開けないときの表示（`device_problems`）も入室時に出る。
- 最後の 1 本が終わってもデバイスを閉じないので、次の相手が入ったときの接続は、デバイスを開き直す時間を含まない。

## Verification

- 要求: `REQ-CON-140`
- `Roster`（`src/network/roster.rs`）の単体テスト: 入室で `Advertise`・`Open` を返す。最後の 1 本が退室しても `End` だけを返す
- `Driver`（`src/network/room_driver.rs`）の単体テスト: 入室で `open_audio` を呼ぶ
- アプリ（`src-tauri/src/session/mod.rs`）のテスト: 相手のいないルームを作ると、デバイスの代わりの入力でセッションが動き、入力のレベルが 0 を超える
