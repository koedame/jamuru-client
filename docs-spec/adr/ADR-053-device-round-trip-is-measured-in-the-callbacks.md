# ADR-053: デバイスの往復の遅延は、出力と入力のコールバックの中でパルスの時刻を測って求める

## Status

Accepted

## Context

低遅延が最優先なので、デバイスまでの往復の遅延（出力バッファ・ドライバ・変換・ケーブル・ドライバ・入力バッファ）を、実機で数字にして持っていたい。バッファの大きさ（32・64・128）や、開くチャンネルの数（[ADR-049](./ADR-049-channels-fit-when-opened-and-pan-follows-the-sender.md)）を変えたときに、遅延が動くかを比べる。

既にある測り方では足りない。

- `debug.audio_tone` と `debug.audio_record` は連続した正弦波を扱うので、どの音が戻ってきたのかを時刻で結べない。2 つの呼び出しは別の要求で、始まる時刻も揃わない。
- `jamjam ... --input-bursts`（`audio::probe`）は、相手を通した全経路（送信・コーデック・回線・ジッターバッファ）の往復で、デバイスだけの遅延は分けて出ない。

## Decision

`audio::device_loop` を足す。`debug.audio_roundtrip`（デバッグの口だけ）が走らせる。

1. 出力のコールバックは、再生するステレオの代わりに、間隔をあけて 32 フレーム（48 kHz で 0.67 ms）のパルスを両側に入れ、残りは無音にする。パルスの時刻は、そのコールバックの始まりの時刻に、コールバックの中の位置を足したもの。2 チャンネル以外のデバイスや選んだチャンネルでも、ステレオを置く前（`place_stereo` の前）に入れるので、選んだ出力チャンネルに乗る。
2. 入力のコールバックは、デバイスから受け取った生のサンプルに閾値を超える音があれば、コールバックの始まりの時刻で「聞こえた」と数え、その時刻より前に出した最も新しいパルスと結ぶ。パルスのあとの 50 ms は数えない。
3. 返すのは、パルスごとの遅延、最小・平均・中央値・95 パーセンタイル・最大、両方のコールバックが 1 回に扱ったフレーム数、入力デバイスのチャンネル数。

測るのは「アプリが出力に渡してから、アプリが入力から受け取るまで」で、アプリが 2 つのバッファで足す遅延と、デバイス・ドライバ・ケーブルの遅延をあわせたもの。分解能は 1 コールバックで、10 ms ごとに呼ぶドライバなら値は真値の上に 10 ms 幅で散る。最小と中央値を読む。

コードは `device-loop` feature の下だけにあり、`debug-tools` が有効にする。それ以外のビルドでは 2 つの空の呼び出しだけが残る（`fault-injection` と同じ扱い）。

## Consequences

- **良い影響**: バッファの大きさとチャンネルの数を変えた実機の遅延を、同じ手順で数字にして並べられる。コールバックの大きさが返るので、要求したバッファの大きさをドライバが守っているか（共有モードで下限に丸められていないか）も見える。
- **悪い影響**: 測っているあいだ出力はパルスと無音に置き換わり、相手の音は聞こえない。ケーブルで繋がっていない環境では何も戻らない（`pulses_heard` が 0）。
- 実機・ケーブルが要るので CI では回らない。パルスの時刻付けと結び付けは、模擬のデバイスを使った単体テストで固定した。
