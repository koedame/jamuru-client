# ADR-065: 1.0.0 の前に、ログ・自動の報告・入室時の環境情報から個人の情報を外す

## Status

Accepted

## Context

1.0.0 までは検証ユーザーだけが使うので、`jamjam.log`・自動の報告・入室時の環境情報（`client_info`）は、伏せずにそのまま送ってよいことにしていた
（[ADR-059](./ADR-059-hang-report-attaches-the-log-before-1-0-0.md)・[ADR-060](./ADR-060-hang-report-attaches-the-log-while-reporting-is-already-on.md)・
[REQ-CON-032](../requirements.md)）。1.0.0 で不特定の人が使い始める前に、送る情報を見直すと決めてあった。

見直す前の状態:

- `jamjam.log` から伏せているのは、IPv4 の末尾・IPv6 の下位 64 ビット・デバイス ID のシリアル・`password` / `token` などの値だけだった。
  ルーム ID・招待コード（入室の鍵になる）・他の参加者の UUID・表示名・ホームフォルダのユーザー名・「〜の AirPods」のようなデバイス名の所有者は、そのまま入る。
- 利用状況の送信がオンの端末は、前回固まったことを見つけると、確認なしで `jamjam.log` を添えて送っていた。
- 入室時に、利用状況の送信の設定に関わらず、デバイスの名前・ID を含む環境情報をサーバーに預けていた。

## Decision

1. **`jamjam.log` に書く時点で、人や場所を特定できる値を伏せる**（REQ-GUI-022）。
   - ルーム ID・招待コードは先頭 2 文字だけ残す。
   - 参加者の UUID は先頭 4 文字だけ残す。
   - 参加者の表示名は `peer1` のような連番にする（自分の名前も同じ）。
   - ホームフォルダのユーザー名は `~` にする。
   - デバイス名は残す（互換性の調査に要る）が、「〜の」「's」の前の所有者の部分は `***` にする。Apple 純正の名前（`MacBook Proのスピーカー`）は所有者でないので残す。
   - ルーム ID・表示名・デバイスの名前と ID は、アプリが知った時点でログの出力側に登録し、どのログ行に出てきても置き換える
     （ログを書く箇所ごとに伏せる指定を足さない）。UUID・ホームフォルダは書式で見つける。
   - コア側のログ（参加者の追加・削除）は、表示名を書かず UUID だけにする。画面側は、招待リンクの URL をログに書かない。
2. **利用状況がオンの端末でも、確認なしで `jamjam.log` を添付しない**（REQ-TEL-023。ADR-060 を置き換える）。
   落ちた・固まった場所は利用状況の `crash` / `hang` に入る。ログが届くのは、「問題を報告」を自分で押したとき（送る前に中身を見られる）と、
   1.0.0 より前の版で、利用状況がオフの端末が確認の画面で「送る」を選んだときだけ（ADR-059。1.0.0 以上では、これも添付しない）。
3. **入室時にサーバーへ預ける環境情報のうち、デバイスの名前・ID・種類・チャンネル数などは、利用状況をオンにした人だけ送る**（REQ-CON-032）。
   版・OS・CPU・メモリ・オーディオ API・設定の値は、これまでどおり常に送る。オフにできる設定を新しく足さない。
4. **AI に読ませる前の伏せ**は、アプリの外（サーバー側で報告のログを取り出す道具）で行う。古い版のアプリは 1 を知らないため。

## Reasons

- 調査に要るのは「種類・版・形」で、誰の値かは要らない。
- 利用状況のオンは「集計した項目」への同意で、他人の識別子を含みうるログまでは含まない。
- 環境の特定には、デバイス以外の項目で足りる。個人の名前が混ざりうるのはデバイス名だけ。

## Consequences

- 1.0.0 より前の検証でも、ログの伏せは効く。調べるときに他人の識別子は見えない（先頭の数文字で突き合わせる）。
- 利用状況がオンの端末の固まりは、ログ無しで届く。ログが要るときは、「問題を報告」を押してもらう。
- 利用状況がオフの端末は、ルームに入るときのデバイスの情報がサーバーに預けられなくなる。
- `JAMJAM_LOG_REDACT=off` は、今までどおり伏せを無効にする（手元の調査用）。
