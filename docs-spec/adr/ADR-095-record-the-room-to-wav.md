# ADR-095: ルームの音を、音声スレッドを止めずに WAV へ録音する

## Status

Accepted

## Context

セッションの音（ルームの聞こえるミックス）を残したい、という要望がある。練習や演奏の振り返りに使う。録音のために遅延や途切れが増えるなら、アプリの目的（低遅延）に反する。また、録音は他の参加者の声を残すので、本人たちに知らせる仕組みと、規約の記述が要る。

すでにあるものを確かめた。

- 仮想出力（`virtual_output.rs`）は、音声スレッドが `rtrb` のリングに音を積み、別のスレッドが読む形で、3 つの取り出し口を持つ。A は自分のマイクの取り込みそのまま、B は相手ごとの音、C は聞こえるミックス（音量・パン・ミュートを反映）。
- `debug.audio_record`（`audio_tap.rs`）は、遠隔の口から指定した秒数だけメモリに録って解析する計測の道具で、WAV はその結果に付けて返すだけ。ファイルを書かず、時間にも大きさにも上限がある。
- ピア間メッセージ（ADR-043）は、サーバーが中身を読まずに参加者へ配る。`feature = peer_message` を持たない古いアプリには届かない。

## Decision

### 形式・保存先・トラック

- **24-bit PCM・ステレオの WAV**（RIFF。ヘッダーは手書き）。サンプルレートはセッションのもの。内部の音は 32-bit 浮動小数なので、16-bit に落とさず 24-bit で残す（ふつうの DAW が読める）。±1.0 を超える値は折り返さず切り詰める。
- **保存先はユーザーの音楽フォルダの `jamuru/`**（無ければ文書フォルダ）。ファイル名は `jamuru-YYYY-MM-DD-HHMMSS.wav`（始めた時刻）。同じ名前があれば上書きせず `-2`, `-3` を付ける。画面は保存先を指定できない（任意の場所へ書かせない）。画面に返すのはファイル名で、パスではない。
- **ファイルは最大 2 つ**。`<名前>.wav` はルームの聞こえるミックス（C）。「自分のマイクも別ファイルに録る」を選んだときだけ `<名前>-self.wav` に自分のマイク（A、エフェクトも音量も掛けない）を書く。相手ごとのトラックは作らない。
- ヘッダーは 1 秒ごとに正しい長さへ書き直す。アプリが落ちても、書けた分までは再生できる。WAV のデータが 4,000,000,000 バイトに達したら、その録音を終える（RIFF の 32-bit の上限の手前）。
- 録音は 1 度に 1 つ。

### 時間をそろえない

ミックス（C、出力デバイスのクロック）と自分のマイク（A、入力デバイスのクロック）は別のクロックで動く。2 つを 1 つのステレオにする・無音で埋めて長さをそろえる、ことはしない。それぞれ届いた分だけを書く。DAW に読み込むときは頭をそろえる必要がある、ということを使い方に書く。

### 音声スレッドを止めない

- 音声スレッドは、固定長のリング（2 秒分）にサンプルを積むだけ。確保も待ちもない。リングが一杯のときは、積めなかったサンプルを数えて捨てる（待たない）。数は録音が終わったときと録音中の状態に出し、画面は「音の一部が欠けています」と言う。
- ディスクへの書き込みは専用のスレッド（20 ms ごとにリングを空にして書く）。
- 録音していないときは、音声スレッドが録音のために行うのは、フラグ（`AtomicBool`）を 1 回読んで戻ることだけ。リングは常にあるが、積まない。デバイスを開き直して音声のコールバックが作り直されても、録音は続く（タップを引き継ぐ）。
- 録音を始める・止めるのはコールバックを作り直さずにできる。

### 録音の取り出し口は仮想出力と共有する

録音の取り出し口は仮想出力と同じ場所（A と C）にあり、リングへ積む処理を 1 つにした。仮想出力のリングと録音のリングは別で、片方が詰まってももう片方に影響しない。仮想出力が無効でも録音できる（取り出し口は常にある）。

`debug.audio_record` とは共有しない。向きが逆だから: あちらは遠隔から指定して短い時間をメモリで測る・解析する道具で、こちらは人が長い時間をファイルへ書く機能。共有できるのは WAV を書く数行だけで、共有して得るものより、計測の道具がファイルや上限の都合を持ち込む損の方が大きい。

### 他の参加者への通知

- 録音を始める・終える（どんな理由でも）と、同じルームの参加者全員へピア間メッセージ `{"recording":{"on":true|false}}` を送る。新しく入室した人には入室時に個別に送る。サーバーは中身を読まない。`peer_message` の無い古いアプリには届かない。
- 受け取ったアプリは、その人の行に「録音中」を出し、チャットに「○○さんがルームの音の録音を始めました／止めました」を残す（文はアプリが UI の言語で作り、送る側の言語に依らない）。
- 自分が録音しているときも、自分の行に「録音中」を出す。

### 規約・プライバシー

- 利用規約の第 7 条（録音）は、「録音は他の参加者に知らされる。ただしそれは了解の代わりにならない。録音するなら参加者全員の了解を取り、法令を守る」と書き換える。利用者に求めることは変わらないので、規約の版は上げない（再同意にしない）。義務を増やす変更のときは上げる。
- プライバシーの説明には、録音が端末の中だけに保存され、運営には送られないこと、開始と終了の知らせがピア間で送られることを書く。
- 通知は同意の代わりにならない（国や州によっては全員の同意が要る）。また、別のソフトや改造したアプリで録る人には知らせられない。この 2 つは法務チェックの表に残るリスクとして書く。

## Consequences

- 録音の取り出し口が音声のコールバックの中にあるので、そこで積む処理の速さが録音の費用になる（下の計測）。
- 録音しているあいだは、リングの 2 秒分より長くディスクが止まると音が欠ける。欠けた量は画面に出る。
- 録音の大きさはディスクと上限で決まる。1 時間のミックスは 48 kHz・24-bit・ステレオで約 1 GB。
- 録音は自分の端末にしか残らず、参加者ごとの別トラックは作れない（要望が出たら B の取り出し口から足せる）。
- 相手に知らせる仕組みは古いアプリには効かない。

## 計測

録音の費用は、音声スレッドの 1 回の積む処理の時間と、書き込みが追いつくか（欠けるか）で測る。`cargo test --release --lib room_recorder_cost -- --ignored --nocapture`（`src/audio/room_recorder.rs`）。48 kHz・64 フレームのステレオのコールバックを実時間の速さで 20 秒間流す（15,001 回）。

| | 1 回の積む処理の平均 | 最悪 | 書けた長さ | 欠けたフレーム |
|---|---|---|---|---|
| 録音していない | 1.07 µs | 8.39 ms | - | - |
| 録音している | 1.66 µs | 4.56 ms | 20.001 s | 0 |

- 平均は 1 回あたり +0.6 µs。64 フレームの周期（1.33 ms）の 0.05 %。計測のための時刻の読み出しを含む。
- 最悪値は録音の有無で逆転している。待ちを持たない処理が数 ms かかるのは、計測した機械の他のプロセスにスレッドを奪われたとき（スケジューラ）で、録音の有無に関係しない。
- 遅延は増えない。録音の取り出し口は音声の経路にバッファを足さず、コールバックが持つ音をコピーして積むだけで、再生や送信の経路は変わらない。実機の前後比較は次のとおり。

実機での前後比較（ベータ版 0.1.0-beta.191、Windows 11・N100・WASAPI 共有・バッファ 128、有線の相手役が 440 Hz を送り続ける。1 区間 20 秒、録音なし→ありを 2 回）:

| | 入力コールバック 平均 / 最大 | 出力コールバック 平均 / 最大 | xrun・starved・underrun | 往復 | ジッター |
|---|---|---|---|---|---|
| 録音なし（2 区間） | 45〜46 µs / 128〜187 µs | 19 µs / 96〜107 µs | 全部 0 | 21.75〜21.76 ms | 0.056〜0.057 ms |
| 録音あり（2 区間） | 45 µs / 162〜171 µs | 19 µs / 99〜110 µs | 全部 0 | 21.75〜21.76 ms | 0.066〜0.069 ms |

- 録音したファイルは 24 bit・2 ch・48 kHz で、長さは画面の経過時間と合う。入れ直さずに 20 秒録ったものは 440.0 Hz・無音区間 0。録音中の退室で録音は終わり、ファイルが残る。
