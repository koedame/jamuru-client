# ADR-082: 更新の確認と入れ替えを、利用者が設定とメニューから自分で頼める

## Status

Accepted。[ADR-041](./ADR-041-self-update.md) と [ADR-076](./ADR-076-notify-newer-release-to-packages-that-cannot-self-update.md) の「更新は画面から動かさない」を、アプリ自身の画面からの確認と入れ替えに限って緩める。署名の検証、上限時間、1 度に 1 つ、セッション中は入れない、は変えない。

## Context

自動更新（ADR-041）は、起動の 20 秒後と 6 時間おきにしか新しい版を探さず、画面からは何も頼めない。次の場面で困る。

- 新しい版が出たと聞いたのに、アプリが気づくまで最大 6 時間待つ。自動更新を止めている（`auto_update = false`）人は、手で入れ直すしかない
- 今の版が何かを、画面で確かめられない（問題を報告するときにも要る）
- Linux の `.deb` と Windows の `.msi` は、新しい版を知らせる（ADR-076）だけで、画面で確かめ直す方法が無い
- メニューバーを作った（[ADR-081](./ADR-081-native-menu-bar.md)）が、macOS・Windows・Linux のどの作法でも「アップデートを確認」はアプリ名メニューかヘルプメニューにある項目で、これが無い

## Decision

1. **設定の「アプリについて」タブに「アップデート」の節を置く。** 実行中の版、「アップデートを確認」、新しい版があるときの「更新して再起動」。タブの分け方（[ADR-080](./ADR-080-settings-tabs-by-what-the-user-is-doing.md)）では「アプリについて」は情報の置き場で、版はそこに属する。
   - 却下: 自動更新の入り切りも同じ節に足す。頼まれたのは確認と実施で、`auto_update` を画面に出さない決め（ADR-041 6 節）は別に決める。
2. **メニューに「アップデートを確認…」を足す**（[ADR-081](./ADR-081-native-menu-bar.md) の「項目を足すとき」に従う）。macOS はアプリ名メニューの「jamuru について」の直下、Windows / Linux はヘルプメニューの「jamuru について」の直前。選ぶと、設定ウィンドウを「アプリについて」タブで開き（開いていれば前面に出して切り替え）、そのまま確認を始める。使える条件は設定と同じ（規約に同意したあとで、メイン・設定のウィンドウから。手伝う側のウィンドウからは使えない）。OS で置き場所が違うので、台帳（`src-tauri/src/menu/ledger.rs`）に理由つきの行を足した。
   - 却下: メニューから結果をダイアログで出す。ネイティブのダイアログは言語と見た目を画面と別に持つことになり、入れ替えのボタンも要る。設定の節と同じ画面にそろえる。
3. **手で頼む確認は `auto_update` に関係なく動く。** 止めている人でも確かめられる。ただし更新のしくみを持たないビルド（開発ビルド・自前のビルド。ADR-041 5 節）は確認せず、そう示す。
4. **入れ替えは、自分で入れ替えられる配布形態だけ。** `.deb` と `.msi` は、確認して新しい版を見つけたとき、これまでと同じ画面上部の知らせを出し、節にも「入れ直してください」と示す（ADR-076）。入れ替えのボタンは出さない。
5. **セッション中は入れない。** 手で頼んだ入れ替えは、背景の更新のように抜けるのを待たず、ダウンロードの前と、入れる前に確かめて断る。画面は、セッション中は「更新して再起動」を押せなくし、理由を示す。再起動で音が切れるのを避けるため（ADR-041 の前提）。待ちたい人のために自動更新がある。
   - 却下: 手で頼んだ入れ替えもセッションを抜けるまで待つ。押した人は結果をその場で見たく、設定ウィンドウを閉じたあとに突然再起動するのは意図と離れる。
6. **頼めるのは、アプリ自身の画面だけ。** 入れ替えは本人の画面からだけ（手伝いの口にも、検査用の口にも開けない）。版と確認の読み取りは、手伝いの口に開けない。署名の検証・取得先・上限時間・1 度に 1 つの制約は、自動更新と同じ経路（`updater.rs` の `install_newer`）を通るので、手で頼んでも緩まない。
7. **この変更ではショートカットを付けない**（ADR-081 6 節のまま）。

## Consequences

- 利用者のアプリが GitHub に接続するのは、起動のたびと 6 時間おきに加えて、利用者が確認を頼んだときになる。送るのはアプリの版と OS の種類だけで、プライバシーの文書の「自動更新のための通信」に書いてあるとおり。
- `docs-spec/api/remote-permissions.md` は、手伝う人にできない操作に、確認と版の読み取りと入れ替えが加わる。
- 設定ウィンドウは、開くときに確認を始めるよう頼める（アドレスの `#/settings/about/check-update`、開いている窓には `settings:check-update` イベント）。
- メニューはネイティブで GUI E2E から押せない（ADR-081）。項目の位置・有効条件・行き先は単体テストで、画面の節はコンポーネントのテストで検証する。入れ替えを通しで動かすのは、これまでどおり実機でしか確かめられない（REQ-UPD-001 の注）。
- 入れ替えが成功するとアプリが再起動するので、画面は結果を受け取らない。
