# ADR-046: 開発は develop で進め、main には出した正式版だけを置く（Git-Flow）

## Status

Accepted

## Context

これまでは main が開発の中心で、main への push のたびに `vX.Y.Z-beta.<実行番号>` のベータ版が公開された
（[ADR-041](./ADR-041-self-update.md)・[ADR-045](./ADR-045-beta-self-update.md)）。作りかけの変更も main に入るので、
正式版を使う人に出すコミットと、動作確認の途中のコミットが同じブランチに混ざる。動作確認が残っているだけの変更も、
確かめるためにはマージして公開するしか無かった。

## Decision

Git-Flow に近い形にする。

- **`main`**: 利用者に出した正式版だけ。`vX.Y.Z` のタグは main に打つ。既定ブランチではない
- **`develop`**: 開発の中心で、既定ブランチ。feature の PR はここへ向ける
- **`release/X.Y.Z`**: develop から切り、版上げなどリリースのための作業だけをする。終われば main へマージして
  `vX.Y.Z` を打ち、develop へ戻しマージし、develop の版を次の版に上げる
- **`hotfix/*`**: 出した正式版の緊急修正。main から切り、main と develop へ入れる（依頼には無かったが、
  Git-Flow の標準の形として足した。使わなければ何も変わらない）
- **ベータ版はタグ `vX.Y.Z-beta.N` を打ったときだけ公開する**（ブランチへの push では公開しない）。
  打つブランチは決めず、develop が基本。feature の動作確認は、最新の develop を feature に取り込んで
  ベータ版を配り、確かめてから develop にマージする。N は同じ X.Y.Z で既に出た最大の N に 1 を足す。
  これまでの実行番号の割り当てをやめるのは、人が打つタグと同じ番号を取り合わないため
- **タグは対になるサーバー側のリポジトリと同じ名前を同じときに打つ**（ベータ版も正式版も）。片方に変更が無くても両方に打ち、
  変更の無い側は 1 つのコミットに複数のタグが付いてよい。版ごとに、どのコミットどうしが前提だったかを
  タグから読めるようにするため

CI（`ci.yml` `build.yml` `e2e-pr.yml`）は main と develop への push と、それぞれへの PR で回る。
ドキュメントとストーリーブックの公開は、これまでどおり main への push（＝正式版）で行う。

## Consequences

- main に入るのはリリースのマージだけになり、main のコミットはどれも出した版か、その修正になる
- ベータ版が自動では出なくなる。動作確認をしたいときは、タグを打つ手間が要る
- develop の版は、正式版を出したあと次の版に上げる。上げ忘れると `X.Y.Z-beta.N` が出した `X.Y.Z` より古い版になり、
  ベータ版が更新として見えない
- 出したベータ版の N は、`v0.1.0-beta.17` までは実行番号だった。次は同じ X.Y.Z の中で 18 から続ける
