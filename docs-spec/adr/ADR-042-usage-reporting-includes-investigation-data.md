# ADR-042: 利用状況の送信に、不具合の調査に役立つ項目（自分の IP アドレス・デバイス ID・接続先）を含める

## Status

Accepted。[ADR-037](./ADR-037-usage-reporting-opt-in.md) の決定 2・4・5 を更新する。

## Context

ADR-037 は、身元や環境が分かる項目（IP アドレス・デバイス ID・自前サーバーの URL）を送らない側に倒していた。その結果、端末のログ（`jamjam.log`）を貼ってもらって調べていた種類の不具合（同じネットワークの相手に音が返らない、接続先が HTTP 530 を返してボタンが効かない、受信が keep-alive だけで切れる）を、利用状況の送信だけでは調べられなかった。失敗したことは載るが、選ばれた経路・接続先・失敗の中身が載らず、原因まで絞れない。

利用状況の送信は、利用者が設定でオンにしたときだけ動く（ADR-037 の決定 1）。オンにした人は、説明文と「送る内容を見る」で何が出るかを確かめられる。

## Decision

1. **調べるのに役立つ自分の情報は送る。** 自分の IP アドレス（相手に伝えた自分のネットワーク上のアドレスと、STUN が見た公開アドレス。ポートは送らない）、選んだ音声デバイスの ID、接続先サーバーの URL を、オンにした利用者の分として送る。
   - URL は、スキーム・ホスト・ポートまで。認証情報・パス・クエリ・フラグメントは秘密が入りうるので落とす。
   - MAC アドレスは取らない。同じネットワークかどうかは経路の種類（`route`）と自分のアドレスで足り、MAC を要る調査が今は無い。要る調査が出たら足す。
2. **相手のアドレスは送らない。** 相手は利用状況の送信をオンにしているとは限らず、その人の IP アドレスに同意していない。両方がオンなら、それぞれが自分のアドレスを送るので、突き合わせは分析側でできる。音声の経路は、アドレスそのものでなく種類（`lan` / `public` / `loopback`）で持つ。
3. **外すのは人を名指しするものと、別の場所で送るものだけ**: `peer_name`（表示名）と `connection_history`（入った部屋の履歴）は送らない。`input_device_id` / `output_device_id` は `settings` から外し、`audio_env` の `input_id` / `output_id` で送る。設定の変更として送ると、デバイスを選び直すたびに `app_start` と `audio_env` の 2 行に割れ、送信のまとまりによっては `audio_env` が「送る内容を見る」から消える。ID は、選んだデバイスが見つからなくて `input` が `null` のときも、選んだ名前として一緒に残したい。設定に人の名前や部屋を特定できるものを足すときは、外す側（`LEFT_OUT`）に入れる。
4. **失敗と経路を、調べられる粒度で送る**: 選ばれた経路の種類と、応答で選ばれたか、接続の所要時間、最初の音声が届くまでの時間、無音で諦めたこと、シグナリングに繋がらなかった理由の区分、サーバー側から閉じられたこと、接続先が既定かどうか。メッセージ本文は送らない。
5. スキーマの版（`v`）は上げない。追加した項目はどれも任意で、定義済みの項目の意味は変えていない。受け口の検証は同じ `schema.json` を読むので、新しい項目を含む行は、受け口が新しい `schema.json` に追いつくまで受け付けられない。

## Consequences

- オンにした利用者の IP アドレスがログに残る。歯止めは、既定オフ・説明文・「送る内容を見る」・オフにすれば ID と未送信の内容を捨てる、の 4 つ。説明文（英語・日本語）と公開のプライバシー文書に、IP アドレスが送られることを書く。
- 自分のアドレスと相手のアドレスが行に混ざらないことは、型（セッションの集計が相手のアドレスを受け取る口を持たない）とテストで守る。
- 接続先の URL が既定と違う利用者は、自前のサーバーのホスト名が残る。それも同じ歯止めの内。
