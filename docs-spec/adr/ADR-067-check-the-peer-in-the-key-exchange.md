# ADR-067: 鍵交換で、ルームの相手が本人であることを確かめる

## Status

Accepted

## Context

[ADR-064](./ADR-064-encrypt-the-audio-link.md) で UDP の通信を暗号化したが、鍵交換は署名しておらず、**相手が本人かどうかは確かめていなかった**。
接続を始める瞬間に、経路上でパケットを書き換えられる者（同じ LAN で ARP を偽る者、経路の途中の機器など）が、両端と別々に鍵を作って間に入れば、
音声を中継しながら聞ける（中間者）。ADR-064 の Consequences に未対策として書き、プライバシーの説明にも「相手の確認はまだしていません」と載せていた。

相手の確認には、**鍵交換の外から届く、相手の身元**が要る。UDP の経路の中で受け取った鍵は、割り込む者が差し替えられる。
一方、アプリはシグナリングのサーバーと `wss` でつながっていて、ルームに入った相手の情報（`PeerInfo`）はそこから届く。経路上の第三者は、これを書き換えられない。

端末識別子（[ADR-024](./ADR-024-device-identity-instead-of-accounts.md)）をその身元に使うと、`PeerInfo` に端末識別子を載せることになり、
「他の参加者へ届く `PeerInfo` に端末識別子を含めない」（REQ-IDT-007）という決定を変えてしまう。

## Decision

1. **入室のたびに、使い捨ての Ed25519 鍵（`LinkIdentity`）を作る。** 公開鍵を `CreateRoom`/`JoinRoom` の `link_key` でサーバーに知らせる。
   サーバーは中身を読まず、他の参加者の `PeerInfo::link_key` にそのまま載せる。端末識別子とは別の鍵なので、REQ-IDT-007 は変わらず、端末識別子は誰にも渡らない。
   端末の鍵で署名して知らせることはしない: 参加者どうしは互いの端末識別子を知らないので、署名を確かめる側がいない。サーバーとの接続は端末の証明で認証済みである（ADR-024）。
2. **鍵交換に署名する。** 署名した鍵交換は 98 bytes（メッセージ・方式 `0x02`・X25519 の一時鍵・署名 64）。署名の対象は、
   `"jamjam-link-key-exchange-v1:"` に、送り手の `link_key`・宛先の `link_key`・一時鍵を続けたもの。宛先を含めるので、あるルームの参加者あてに署名されたものを別の参加者に見せても通らない。
   署名は `SecureLink` を作るときに 1 度だけ行い、250ms ごとの再送では使い回す。
3. **相手の鍵が分かっているリンクは、署名された鍵交換だけを受け付ける。** 署名の無いもの（方式 `0x01`）も、別の鍵で署名されたものも捨てる。
   このリンクは、平文のパケットが届いても暗号化をやめない（ADR-064 の「暗号化できない相手」の見分けは、相手が `link_key` を知らせた時点で、その相手には当てはまらない）。
   これで、鍵の差し替えも「平文に落とさせる」引き下げも、割り込む者にはできない。
4. **相手の鍵が無いリンクは、これまでどおり。** 相手のアプリが `link_key` を知らせない古い版のときは、
   署名の無い鍵交換で暗号化して繋ぐ。相手が本人かは確かめない。`SecureLink::checks_peer` で区別できる。相手の鍵として読めない値も、鍵が無いものとして扱う。
5. **確かめ方は、割り込む中継。** `tests/wire_encryption_test.rs` に、両端の鍵交換を自分の鍵に差し替え、両端と別々に鍵を作り、開いた音声を渡し直す中継を置く。
   同じ中継が、相手を確かめない接続では音声を聞け、確かめる接続では鍵ができず何も聞けないことを並べて見る。

### 選ばなかったもの

- **鍵交換そのものをシグナリング経由（`PeerMessage`）にする**: 割り込みには強いが、サーバーを使わない直接接続・echo・音質チェックのボットが別の手順を持つことになり、
  鍵交換が UDP の経路の外の往復に依存して、入室から音が出るまでが延びうる。公開鍵 1 つを知らせるだけで済む方式を選んだ。UDP 上の手順は ADR-064 のまま。
- **端末識別子で署名して `PeerInfo` に載せる**: REQ-IDT-007 を変える必要があり、参加者どうしが互いの端末を見分けられるようになる。必要が無いので、決定を変えなかった。
- **古い相手を断る**: 配布中のベータ版どうしが更新の途中で繋がらなくなる。ADR-064 と同じく、正式版（1.0.0）を出す前に決める。

## Consequences

- **経路上の第三者に対しては、相手が本人であることを確かめられる**: 割り込む者は、相手の `link_key` に対応する秘密鍵を持たないので、署名を作れない。
- **鍵を配るシグナリングのサーバーは、信じる前提になる。** サーバーが偽の `link_key` を配れば、その相手との間に入れる。運営者が参加者の音声を聞く経路としては使わない前提だが、技術的には防げない。
- **確かめない接続が残る。** 古い版の相手など、`link_key` を使わない手順（サーバーを使わない CLI の直接接続は [ADR-071](./ADR-071-remove-direct-connection.md) で無くした）。これらは ADR-064 の水準（暗号化されるが、相手の確認はしない）に留まる。
- **入室から音が出るまでの時間は、署名 1 回と検証 1 回の分だけ延びる。** ループバックで接続してから最初の音がコールバックに届くまでは、確かめる接続でも確かめない接続でも 12 ms で差が見えなかった。接続が続いている間の遅延も、パケットごとの処理が同じなので変わらない（測定は `tests/wire_latency_measure.rs`）。
- 入室のたびに新しい鍵を作るので、ルームに入り直すと鍵が変わる。
