# ADR-085: アプリは 1 人につき 1 つだけ動かし、2 つ目の起動は 1 つ目に渡して終わる

## Status

Accepted。[ADR-025](./ADR-025-gui-e2e-control-channel.md) の「アプリはシングルインスタンス化しない」を、製品としては置き換える
（GUI E2E が複数のアプリを同時に起動することは変えない）。

## Context

Windows と Linux では、招待 URL（`jamuru://join/<code>`）を開くと、OS はアプリの実行ファイルをもう一度起動する。アプリがすでに動いていると、
同じユーザーのアプリが 2 つ動くことになる。2 つのアプリは次を共有する。

- 設定ファイル（`config.toml`）。ただし設定の本体は各アプリのメモリにあり、保存のたびにメモリの全体をファイルに書く。
  片方で変えたバッファサイズはもう片方のメモリに届かず、もう片方の入室は古い値で始まる。古いほうが何かを保存すると、新しい値をファイルから消す。
- 音声デバイス、遠隔デバッグの登録（同じ端末 ID の接続は 1 つだけ）、ログファイル。

このため、バッファサイズを保存した直後の入室が、保存前の値で始まることがある。

## Decision

- Tauri の `tauri-plugin-single-instance`（`deep-link` 付き）を、ほかのプラグインより先に登録する。2 つ目のアプリは起動引数（招待 URL）と作業ディレクトリを
  1 つ目に渡して終了する。URL は deep-link プラグインに転送され、入室は 1 つ目が受ける。1 つ目は主ウィンドウを復元して前に出す。
- GUI E2E の制御ポート（`JAMJAM_E2E_CONTROL_PORT`）が設定されているあいだは、このプラグインを登録しない。E2E の試験と、相手役の端末が、
  独立した `$HOME` で複数のアプリを同時に起動する（ADR-025 §8）。
- 再起動が本流で終わらず、止まった古いプロセスを残して新しいアプリを起動する経路（ADR-055 の `start_new_instance`）では、新しいアプリを起動する前に
  プラグインのロックを手放す。手放さないと、新しいアプリが止まった古いアプリに引き継いで終わり、どちらも動かない。通常の再起動は、
  Tauri の終了イベントでプラグインが自分で手放す。

## Consequences

- 招待 URL を開いたとき、すでに動いているアプリが前に出て入室する。2 つ目の窓は開かない。
- Linux では D-Bus のセッションバスの名前、Windows では名前付きミューテックス、macOS では UNIX ソケットで 1 つ目を見つける。
  Linux でセッションバスに繋げなければ、保護なしで起動する。
- アプリを複数同時に使いたい開発者は `JAMJAM_E2E_CONTROL_PORT` を設定する（`e2e-control` 付きのビルドでだけ意味がある）。
- 依存が増える（Linux では zbus とその依存）。第三者ライセンスの表示を作り直す。

## Verification

- `single_instance.rs` の単体テストで、E2E の制御ポートがあるときだけ登録しないことを確かめる。
- `tests/e2e/tests/gui.rs` で、招待 URL つきの 2 つ目の起動が終了し、1 つ目が動き続けることを確かめる（REQ-CON-143）。
