# ADR-038: 送信チャンネル設定は、取り込むチャンネル数を決める。線路は常にステレオ

## Status

Accepted

## Context

設定の「送信チャンネル」（モノラル/ステレオ、`transmit_channels`）は保存され、相手のミキサーに「モノラル/ステレオ」と表示されるだけで、送る音には何も影響していなかった。キャプチャは常に 1 チャンネルで開かれ、REQ-AUD-108（ステレオ入力で 2 チャンネルが送信される）は実装されていなかった。検証するはずのテストは `CaptureConfig { channels: 2 }` を作って `assert_eq!(channels, 2)` するだけで、キャプチャから送信までを一度も通していなかった。

帯域・遅延・ジッタバッファへの影響は問題にならない。**線路はすでに常にステレオ**（[ADR-028](./ADR-028-single-stage-playout.md) の受信経路、`WIRE_CHANNELS = 2`）で、送信側が定位（パン）を適用した左右を送る。符号化設定・帯域見積もり（`required_bps(.., 2)`）・フレーム長・ジッタバッファはすべてステレオ前提で計算されており、モノラルの取り込みを 2 チャンネルに複製して送っていたにすぎない。ステレオで取り込んでも、パケットの大きさ・数・間隔は変わらない。

## Decision

1. **`transmit_channels` は取り込むチャンネル数を決める。** 1 ならデバイスを 1 チャンネルで開き、パンで定位させて左右に置く（従来どおり）。2 なら 2 チャンネルで開き、左右を混ぜずに送る。線路の形式は変えない。
2. **ステレオの取り込みでは、ローカルのパンはバランスとして働く。** 向いた側は変えず、反対側を絞る。中央は素通し（モノラルの等パワー則は中央で各側 −3 dB になるが、既にステレオの音を中央で下げる理由はない）。`capture_to_wire`（`src/audio/stream.rs`）が両方を扱う。
3. **2 チャンネルで開けないデバイス（モノラルのマイクなど）は、1 チャンネルで開き直す。** 設定が「ステレオ」でも入力が無い状態にしない。相手へ伝える `channel_count` は、設定ではなく実際に取り込んでいる数にする。
4. **接続中に設定を変えたら、その場でキャプチャを開き直す。** 入力デバイスを切り替えたときも、新しいデバイスで 2 → 1 の落とし直しをして、`channel_count` が変わったら相手に送り直す。
5. **ローカルモニタリングは、ステレオの取り込みでは左右の平均を聞く**（[ADR-033](./ADR-033-local-monitoring.md) のとおりモノラルのまま）。ステレオでモニターするなら、モニターのリングを 2 チャンネルにする別の決定が要る。

## Consequences

- REQ-AUD-107/108 の検証は、`capture_to_wire` → `Connection::send_audio` → UDP → PCM デコードを実際に通す（`tests/audio_quality_test.rs`）。
- 入力チャンネルの選択（`input_channel_l` / `input_channel_r`。多チャンネルのインターフェースの何番を使うか）は [ADR-040](./ADR-040-input-output-channel-selection.md) で配線した。
- 実デバイスでの動作（2 チャンネルで開けない場合の落とし直し、接続中の切り替え）は自動テストの外にあり、実機で確かめる（`Plans.md`「実環境待ち」）。
