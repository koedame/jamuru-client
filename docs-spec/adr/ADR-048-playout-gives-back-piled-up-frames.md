# ADR-048: 再生バッファが目標より深く溜め込み続けたら、余分を 1 回で捨てる

## Status

Accepted

## Context

[ADR-046](./ADR-046-audio-gaps-are-measured-not-guessed.md) が、再生バッファ（`PlayoutBuffer`）の深さ（保持しているフレーム数 = 聞こえる遅延）は**増える一方**であることを見つけた。深さは 2 つの経路で増え、減る経路が無かった。

- **空読み（`Starved`）**: 来るはずのフレームが無く後続も無い読み出しは、無音を出して**再生位置を進めない**。送り手は進み続けるので、次の読み出しからは 1 フレーム深い
- **デバイスの読み出しの遅れ**: 読み出しが止まっている間に届いたフレームは、そのまま溜まる

減るのは、リング（全プリセットの最大段数で確保。38 フレーム = 約 51ms）が溢れて `write` が再同期（`resync_to`）したときだけだった。再同期は保持中の全フレームを捨て、起動し直すので、そのあとに 2 フレーム前後の無音（`Priming`）が出る。`adapt()` が目標の段数を下げても、[ADR-031](./ADR-031-live-playout-delay.md) の「減らす」が捨てるのは目標を下げた差分だけで、空読みと読み出しの遅れで溜まった分は捨てなかった。

Linux の 2 台（PipeWire の仮想デバイス。ホストが混んでいる）を 25 秒繋ぐと、再同期が 5〜10 回、飛んだ距離は毎回 38、そのたびに `primed` が続いた。

## Decision

読み出しのたびに、その時点の保持数を**窓（500 読み出し。64 サンプル・48kHz で約 0.67 秒）の最小値**に取り込む。窓が終わったとき、最小値が「目標 + 1」（再生中の平常。保持数は読み出しの位相で 1 上下する）を **2 フレーム以上**超えていたら、超えた分を再生位置から**1 回の飛びで捨てる**。窓は捨てたあと・目標を動かしたあと・再同期と `reset` のあとに数え直す。

| 窓の最小値（目標 + 1 との差） | 動作 |
|---|---|
| 0〜1 | そのまま。1 フレームの余りは平常の位相と区別できず、捨てるとその分の飛びが無駄になる |
| 2 以上 | 差の全部を捨てる。ここから先の窓は、差が 0 になるので捨てない |

- **最小値で見る理由**: バーストが来た直後の一瞬の深さや、位相の揺れで判断しない。窓の間ずっと目標より深かったなら、その分は一度も使われていない（窓の間に空になりかけた回線は、最小値が小さいので何も捨てない）。空読みは保持数 0 の読み出しなので、途切れている回線は自然に捨てない
- **1 回で全部捨てる理由**: 飛びごとにクリックが出うる。1 フレームずつ数回に分けると、クリックの数が増える
- **窓の長さ・閾値は保持数で数える**（時間ではなく）。`PlayoutBuffer` はサンプルレートを持たないので、フレームの大きさによって窓が伸び縮みする。伸びるほど慎重な側に倒れる
- **捨てる位置**: ADR-031 の「減らす」と同じ、再生位置から。そのため `trim_excess` を共有し、`pending_shift`（負）として積む
- **記録**: 捨てたフレーム数を `PlayoutStats::frames_trimmed` に、飛びを飛行記録の `trimmed`（値 = 捨てたフレーム数）に残す。目標を下げたときの飛びも同じ計数に入る
- **`adapt()` は変えない**。欠け率の判定は、捨てたことの影響を受けない（捨てるのは目標を超えた分だけで、欠けではない）

**選ばなかった案**

- **深さが目標 + 余裕を超えた瞬間に捨てる**: 位相の揺れと、バースト直後の一瞬の深さで捨ててしまい、その直後の空読みを招く（捨てる → 空になる → 深くなる → 捨てる、の往復）
- **タイムストレッチや、無音区間まで待つ**: ADR-031 が選ばなかった理由と同じ
- **空読みで再生位置を進める**: ADR-026 が退けた。遅れて届くフレームがすべて遅れになり、再生が戻らなくなる

## Consequences

### 良い影響

- 再同期に頼らず、目標に戻る。再同期がもたらす保持中の全フレームの破棄と 2 フレーム前後の無音が、少なくとも 1 回の小さな飛び（溜まった分だけ）になる
- 聞こえる遅延が、表示している段数から 1 フレームを超えて離れたままにならない

### 悪い影響・残る作業

- **窓ごとに最大 1 回、溜まった分だけ音が飛ぶ**。溜まり方が速い環境では、窓ごとに飛びが出る。飛びの数は `trimmed` で数えられる。飛ばさない方法（タイムストレッチ）は ADR-031 のとおり、必要と分かるまで採らない
- 窓は約 0.67 秒（64 サンプル・48kHz）。これより短く目標を超えてまた戻る揺れには反応しない

### 検証

| 要求 | 検証 |
|------|------|
| REQ-LAT-025 | `src/audio/playout.rs` のテスト（読み出しが止まって溜まったフレームが目標まで戻る・1 回の飛びで捨てる・1 フレームの余りは捨てない・バーストで届く回線の深さは捨てない・パススルーも戻る）、`src/audio/stream.rs` の飛行記録のテスト |
