# ADR-031: 再生中の段数変更と自動調整を、実際に保持する量へ効かせる

## Status

Accepted

## Context

[ADR-028](./ADR-028-single-stage-playout.md) で溜める場所は `PlayoutBuffer` 1 か所になり、保持している量が聞こえる遅延になった。ところが「段数」を再生中に動かす経路は、保持量に届いていなかった。

1. **段数の変更が保持量に効かない。** `set_target_delay_frames` が動かすのは目標値だけである。起動条件（`ready > target`）は再生開始時にしか見ないので、再生が始まった後で目標値を変えても、溜まっているフレーム数は変わらない。GUI でプリセットを切り替えると、遅延表示と相手への通知は新しい段数になるのに、聞こえる遅延は接続し直すまで変わらない
2. **プリセット切り替えの段数が、接続時のプリセットの範囲で切られる。** 範囲（`min` / `max`）は生成時のプリセットから決まる。`balanced`（下限 1）で接続して `zero-latency`（0）へ切り替えると 1 に切られ、`zero-latency`（上限 2）から `high-quality`（8）へ切り替えると 2 に切られる。表示は切り替え先の値のままなので、これも表示と実際が食い違う。再接続（`reset`）は接続時の段数へ戻すので、切り替え後のプリセットも失われる
3. **`adapt()` を誰も呼んでいない。** REQ-LAT-108 の「バッファサイズを調整しました」という通知も無い。要求はライブラリ単体のテストで検証済みになっていて、実経路では動いていなかった（[ADR-020](./ADR-020-jitter-buffer-wiring.md) が「適応の有効化は別途判断する」と残した）
4. **`adapt()` の判定が累積値だった。** 接続開始からの補間率で判断するので、一度損失が出ると 5% を下回るまで長く、呼ぶたびに段数が上限へ向かって増え続ける。実経路へ繋ぐと、これが実際の遅延になる

## Decision

### 1. 段数の変更は、保持量を動かす

再生中に目標値を動かしたら、差分だけ保持量を動かす。

| 変更 | 動作 | 音への影響 |
|------|------|-----------|
| 増やす（+k 段） | 次の k 回の読み出しで**無音を出し、再生位置を進めない**。その間に届いたフレームがそのまま保持量になる | k フレーム分の無音が入る |
| 減らす（-k 段） | 溜まっているフレームが目標より多いとき、**再生位置にあるフレームから k 個を捨てる** | k フレーム分が飛ぶ |

- 起動前（`Priming`）は起動条件が目標値を直接見るので、何もしない
- 増やす無音は `PlayoutResult::Padded` として返す。`Priming` / `Starved` とは別で、アンダーランとして数えない（数えると、調整が調整を呼ぶ）。補間（`Concealed`）でもないので `frames_concealed` に入れず、`adapt()` の入力を汚さない
- 減らすときは、読み出しの時点で保持量が目標を超えている分だけ捨てる。ジッタで既に目標以下まで減っていれば、それ以上は捨てない（すでに目標に達している）
- 変更が重なったら差分を足し合わせる。増やす → 減らすは相殺する
- 再同期（`resync_to`）と `reset` は、保留中の差分を捨てる

**選ばなかった案**

- **タイムストレッチ**: 音の途切れは最も小さいが、遅延ゼロを目指すアプリに、位相ずれと計算量を持ち込む。ピッチ保存（ADR-028 §3）の検証も増える。無音・破棄で足りないと分かったときに再検討する
- **次の無音区間まで待つ**: 演奏では無音区間が来る保証が無い。段数を変えたのに変わらない時間が続き、「表示と実際が食い違う」を別の形で残す

無音・破棄は、変更時に 1 回だけ起こる。自動調整はこれを頻繁に起こしてはならないので、§3 で歯止めを掛ける。

### 2. プリセットは段数と範囲を一緒に決める

プリセットの切り替えは `PlayoutBuffer::set_delay`（`ReceivePath::set_delay_frames`）で行う。

- 段数を目標値に、範囲を `PlayoutConfig::for_delay(段数)` に置き換え、**基準の段数**（`reset` が戻る先）も更新する
- リングは**全プリセットの最大段数**（`AudioPreset::all()` から求める）で確保する。切り替えでリングを作り直さない（リアルタイム側が触っているので、確保・移動は許されない）
- 自動調整（`adapt`）は範囲の中で目標値だけを動かす。基準の段数は動かさないので、`reset`（再接続）は基準へ戻る

### 3. 自動調整を受信経路から呼ぶ

`src-tauri/src/streaming.rs` の統計ループが 1 秒ごとに `adapt()` を呼ぶ（CLI のセッションも同じ周期 `ADAPT_INTERVAL` で呼ぶ。[ADR-038](./ADR-038-cli-round-trip-measurement.md)）。判定は**直近の区間**の補間率で行う（累積ではない）。

| 区間の補間率 | 動作 |
|-------------|------|
| 5% 超 | 段数を 1 増やす（上限まで）。きれいな区間の連続はリセット |
| 1% 未満 | きれいな区間として数える。**10 区間（10 秒）続いたら**段数を 1 減らす（下限まで）。数え直す |
| その間 | そのまま。きれいな区間の連続はリセット |

- 区間の標本が 20 フレームに満たなければ判定を見送り、次の呼び出しへ持ち越す
- 増やすのは 1 区間で、減らすのは 10 区間続いてから。増減が交互に起きると、そのたびに無音か破棄が入る（ハンチング）。減らした直後に損失が出て増やす往復を、非対称な閾値で抑える
- **パススルー（`zero-latency`、段数 0）は固定**（`min == max == 0`）。ゼロ遅延の約束（ADR-008、REQ-LAT-111）を、聞き手に知らせずに崩さない。それ以外のプリセットは適応（`min < max`）
- 旧仕様の「段数より多く溜まっていれば減らす」は外す。溜まっている量は再生の位相で 1 フレーム上下するので、任意の瞬間に読んだ値は「余っている」の根拠にならない

### 4. 表示・通知は、バッファの実際の段数から出す

遅延表示と相手への通知（`LatencyInfoMessage`）は、コマンドを受けた時ではなく、**統計ループがバッファの段数を読んで、変わっていたら**更新する。プリセット切り替え・自動調整・再接続による基準への復帰が、同じ 1 経路で表示に届く。

`adapt()` が段数を動かすたびに、`AudioQuality::delay_adjustments` が 1 増える。UI はこの増加を見て「バッファサイズを調整しました」を数秒表示する（REQ-LAT-108）。プリセット切り替えは利用者自身の操作なので、これには数えない。

ADR-028 の「セッション中の段数変更が、バッファ破棄による音切れを伴わなくなった（目標値を動かすだけ）」は、本 ADR が上書きする。目標値だけ動かして保持量が動かないのが、上の 1 だった。

## Consequences

### 良い影響

- 段数を変えたら、聞こえる遅延が変わる。表示と実際が一致する
- プリセットをどの向きに切り替えても、切り替え先の段数どおりになる（範囲に切られない）
- REQ-LAT-108 が実経路で動く。検証も実経路の部品（`PlayoutBuffer` と `ReceivePath`）で行う
- 自動調整が一度の損失で上限まで登り詰めない

### 悪い影響・残る作業

- **段数の変更に音の途切れが 1 回入る。** 増やすときは無音（k × 1 フレーム。64 サンプル / 48kHz で 1.33ms × k）、減らすときは波形の飛び。飛びの位置ではクリックが出うる。プリセット切り替えは利用者の操作なので許容する。自動調整は 10 秒以上の間隔でしか減らさない
- `for_delay` の 0 は範囲が `0..=0` になる。`PlayoutBuffer::set_delay` で 0 から他へ切り替えると、範囲も切り替え先のものへ置き換わる
- 増やす無音の間に届くフレームが、その分だけ余分にリングを使う。リングは全プリセットの最大段数で確保しており、収まる

### 検証

| 要求 | 検証 |
|------|------|
| REQ-LAT-108 | `src/audio/playout.rs` の適応テスト（区間の補間率で増える・上限で止まる・累積ではなく直近の区間で判定する・縮めるのは 10 区間続いてから）、`src/audio/stream.rs` の `ReceivePath::adapt`（受信経路が呼ぶ部品）。通知の表示は `ui/src/screens/MainScreen.tsx`（型検査とビルドまで。表示そのものは実アプリでの手動確認） |
| REQ-LAT-109 | 同ファイルの適応テスト（きれいな区間が続いても下限で止まる） |
| REQ-LAT-110 | 同ファイルの固定テスト（`min == max` は `adapt()` で動かない）。パススルーも固定 |
| REQ-LAT-106 | `src/audio/playout.rs` の `set_delay` テスト、`src/audio/stream.rs` の全プリセット相互切替テストと、切替後の出力が `Padded` になるテスト、`src-tauri/src/streaming.rs` のプリセット→遅延テスト |
| REQ-LAT-025 | 増やす・減らすテスト（再生中に段数を変えると、保持量が新しい段数へ収束する） |
