# ADR-097: 機器の遅延は、測定用の音を鳴らして、戻ってくるサンプルの位置で測る

## Status

Accepted。デバッグ用の [ADR-053](./ADR-053-device-round-trip-is-measured-in-the-callbacks.md)（コールバックの時刻で往復を測る）を、リリースビルドの設定の機能にする。ADR-053 の `debug.audio_roundtrip` は、デバッグの口として残す。

## Context

遅延は、アプリが足すバッファのほかに、機器・ドライバ・ケーブルの分がある。この分は機器ごとに違い、設定の手伝い（[ADR-044](./ADR-044-portals-and-permissions.md)）でバッファの大きさを一緒に決めるときも、その人の機器がどれだけ遅いかが分からない。また、ルームのほかの人が自分の機器の遅延を知っていれば、合奏の遅れの見積もりに使える。

ADR-053 の測り方はデバッグ専用で、足りないところがある。

- パルスは 32 フレームの固まりで、聞こえたかどうかをコールバックの始まりの時刻で数える。分解能が 1 コールバック（10 ms ごとに呼ぶドライバなら 10 ms）になる。
- 閾値は固定で、雑音のある部屋や、小さい音しか戻らない経路では、聞こえたかどうかが当てにならない。
- 結果を保存せず、ほかの人に伝える口も無い。

## Decision

1. **測定用の音は 2 種類。** まずクリック列（1 サンプルのパルスを 1 ms おきに 30 ms 並べたもの）。聞き取れなければ、1 kHz の正弦波（40〜60 ms）にする。正弦波は 1 kHz のバンドパス（Q=2）を通してから判定し、帯域の外の雑音に埋もれにくくする。
2. **サンプルの位置で測る。** 出力のコールバックは、測定用の音を始めたサンプルに、そのコールバックの始まりの時刻を付ける。入力のコールバックは、受け取ったバッファごとに「終わりのフレーム番号と時刻」を控える。音が入力で見つかった位置から、バッファの終わりまでのフレーム数を引けば、音が届いた時刻がサンプル単位で出る。さらに、立ち上がりの始まりまで遡る（振幅が雑音を超えた位置ではなく、上がり始めた位置を取る）。
3. **雑音から閾値を決める。** 鳴らす直前の 300 ms の振幅の P90 を雑音とし、閾値は雑音の 10 倍（20 dB）。音量の段が上がった最後の 3 段は、12・9・6 dB に下げる。雑音が 1e-4 未満のときは 1e-4 とする。10 ms 以上続かない山（スパイク）は音として数えない。
4. **音量は 8 段、各段 5 回。** 約 −48 dBFS から 6 dB ずつ −6 dBFS まで。聞こえない段は次の段へ進む。音の戻りを待つのは 1 回あたり 750 ms で、全体は 90 秒で終える。
5. **漏れ込みを捨てる。** 出力から入力へ 2 ms 未満で戻る音は、経路を通った音ではなく漏れ込みとして捨てる（2 ms 以上の経路は測れる）。
6. **結果を決める。** 聞こえた回の遅延の中央値から、`max(4.4478 × MAD, 3 ms)` より離れたものを外れ値として除く。3 回以上が残り、その幅が 25 ms 以内で、中央値が 500 ms 以内なら、中央値を結果にする。足りなければ、音が戻らなかった・ばらついた・遅すぎる、のどれかで終わる。ばらつき（残った値の幅）が 2 ms 以内なら「安定」、6 ms 以内なら「ややゆれる」、それ以上は「ゆれる」。100 ms を超えたら、設定の見直しを案内する。
7. **測っている間、セッションに渡る入力は無音にする。** 測定用の音が相手に聞こえず、部屋の人の音が測定に混ざらない。測っていないときは、コールバックは旗を 1 回読むだけで、音は変えない。
8. **結果は設定に保存し、数字だけをルームに伝える。** 保存するのは、遅延・ばらつき・測った入力と出力のデバイス ID・バッファの大きさ・サンプルレート・測った時刻。選んでいる機器・バッファ・サンプルレートがこれと違うときは、今の機器の値として使わない（出さない・伝えない）。ルームには、遅延を 0.1 ms 単位の数字だけで、ピア間メッセージで知らせる（[ADR-095](./ADR-095-record-the-room-to-wav.md) の録音の知らせと同じ形）。
9. **手伝う人は測り始められない。** 音が手伝われる人のスピーカーから出る。測る操作（始める・止める）は手伝う側に許さず、進み具合と結果を読むことだけ許す。

## 測った条件と結果

実機の音声機器はこの環境に無いので、時計と機器を模擬して（出力から入力への遅延・音量・雑音・漏れ込みを決めた機器を、実際の `output_at` / `input_at` に繋ぎ、仮想の時計で回す）測った。結果は決まった値で再現する。

| 条件 | 結果 |
|---|---|
| ケーブルのみ。真の遅延 3・23・180 ms | 3.00・23.00・180.00 ms（誤差 0） |
| バッファが 10 ms（10 ms ごとのコールバック）。真の遅延 23 ms | 23.00 ms。バッファ単位に丸まらない |
| 経路が小さい音しか返さない（利得 0.01） | 音量が上がり、−18 dBFS のクリックで検出。誤差 0 |
| 雑音が大きく（±0.02）、利得 0.02 | クリックは雑音に埋もれ、正弦波に切り替わる。−6 dBFS で 31.73 ms（真値 31 ms）、ばらつき 0.5 ms |
| 雑音がさらに大きい（±0.05） | 36.1 ms、ばらつき 13.1 ms で「ゆれる」。値を信じてはいけない状態を、そうと示す |
| 何も戻らない | 音が戻らなかった。90 秒以内に終わる |
| 出力から入力へ 1 ms で漏れる | 捨てる（経路として数えない） |
| 3 ms の経路 | 測れる |

アプリへの影響（測っていないとき）:

- **遅延**: バッファ・ジッターバッファ・リサンプラ・コーデックの段は変えていない。コールバックに足したのは、旗の読み 1 回（出力と入力の 1 組で 1.2 ns、release ビルド、5,000,000 回の平均）だけ。往復の遅延（`roundtrip_total_ms`）と受信側のバッファの各段は、段を足していないので変わらない。
- **音質**: 測っていないとき、出力も入力も 1 サンプルも書き換えない（テスト `when_no_run_is_under_way_the_callbacks_leave_the_sound_as_it_is` が、出力と入力が同じ値のままであることを確かめる）。

実機では、ケーブルでつないだオーディオインターフェースと、スピーカーとマイクの 2 通りで、`debug.audio_roundtrip`（ADR-053）の中央値と比べる。これは実機での動作確認の手順に入れる。

## Consequences

- **良い影響**: 設定の手伝いで、その人の機器の遅延が数字で分かる。測った結果の安定の度合いが分かるので、信じてよい値かが分かる。ルームの人が互いの機器の遅延を知れる。
- **悪い影響**: 測っている間（最長 90 秒）、その人の音は部屋に出ない。スピーカーから測定用の音が出る（小さい音から段階的に大きくなる）。測定にはケーブルか、スピーカーの音をマイクが拾える配置が要る。
- ルームの人に伝わるのは遅延の数字だけ。機器の名前や ID、音は伝わらない（プライバシーの説明にもそう書いた）。
- 測定用の音の細かい形（パルスの間隔・段数・待ち時間・閾値）は、模擬の機器で決めた値で、実機の機器の癖で変えることがある。変えるときはこの ADR に追記する。
