# ADR-058: 設定に「問題を報告」を置き、`jamjam.log` と一言のコメントを、利用状況の送信とは別の経路で送る

## Status

Accepted

## Context

[ADR-056](./ADR-056-hang-detection-and-reporting.md) は、正常終了しなかった前回の起動を自動で 1 回だけ報告する仕組みを作ったが、
生ログを添える「問題を報告」ボタン自体は範囲外にした。利用者が今困っている不具合（音が出ない、繋がらない等）を、
`jamjam.log`（[ADR-036](./ADR-036-diagnostic-log-file.md)）を手元から探して GitHub Issue に貼る手間なしに、その場で送れる手段が無い。

利用状況の送信（[ADR-037](./ADR-037-usage-reporting-opt-in.md) / [ADR-042](./ADR-042-usage-reporting-includes-investigation-data.md)）は
既定オフの集計データで、ルーム ID・他の参加者の識別子・サーバー URL の類は載せない設計である。一方 `jamjam.log` はそれらを
含みうる（ADR-036 の Consequences）。この 2 つを同じ経路に混ぜると、利用状況の送信を切っている利用者の生ログが紛れ込む
危険があるため、ADR-037 決定 7 のとおり別経路に保つ。

## Decision

### 1. 何を送るか

1. **送るのは、現在の `jamjam.log` の末尾 512 KiB とコメント（最大 2000 Unicode スカラー値）だけ**（REQ-RPT-003・004）。
   ログ全体（最大 15 MiB、ADR-036 §6）ではなく末尾を選ぶのは、直近の出来事が今の不具合に最も関係するため、また
   低速な回線でも送信が速く終わるため。切り詰めたときは先頭に省略の印を 1 行付ける。
   - 却下: ローテーションした過去 2 世代も送る。今困っている不具合には現在のファイルで足りる。要る調査が
     出たら「ログのフォルダを開く」（既存）で手動添付できる
2. **マスクは ADR-036 §7 の既存の関数をそのまま使う。新しいマスクは足さない。** `jamjam.log` は元から
   「共有する前提で読み返す」ファイルであり（ADR-036 Consequences）、この機能は利用者が今まで GitHub Issue に
   手で貼っていたのと同じファイルを、同じマスクを通したまま送るだけである。むしろ jamjam 自身の非公開の受け口に
   送るほうが、公開の GitHub Issue に貼るより公開範囲は狭い。
   - 参加者の識別子やルーム ID がログに残る点は ADR-036 が既に受容している risk であり、本 ADR で新たに広げるものではない
3. **コメントは自由記述で、上限を超えた分は静かに切り詰める**（エラーにしない）。画面側は `maxLength` 属性で
   先に上限を掛けるので、実際に切り詰めが起きるのは Tauri コマンドを直接叩く経路（e2e 等）だけ

### 2. 同意の取り方

4. **専用の設定は置かない。「送信する」を押す操作そのものが、その 1 件だけの同意である**（REQ-RPT-001）。
   `usage_reporting` の値を読まず、送っても変えない。既存の「利用状況の送信」トグルと独立させる理由は、
   これが継続的な集計ではなく、利用者が今、今困っている 1 件を選んで送る単発の行為だからである
   - 却下: `usage_reporting` を先にオンにすることを要求する。仕組みの都合を利用者に説明する負担が増え、
     「困っているから送りたい」という動機と無関係な前提を挟む
5. **送信前に、送る `jamjam.log` の内容をそのまま表示する**（REQ-RPT-002。「送る内容を見る」と同じ発想）。
   プレビューを取得するコマンドと送信するコマンドは同じ `read_log` 関数を呼ぶので、表示と送信は常に一致する

### 3. どこに置くか

6. 設定の Diagnostics タブに、既存の「ログファイル」節の下に「問題を報告」の節を置く。ログファイル節（フォルダを開いて
   手で添付する）と共存させ、この機能はその手間を省く追加の手段とする

### 4. 権限

7. **設定の手伝い（ADR-044）からは呼べない** (`Access::NO_HELP`)。手伝う人には診断ログが渡らない既存の方針
   ([remote-permissions.md](../api/remote-permissions.md)) のとおり、ログの中身を読むプレビューも送信も対象外にする

### 5. サーバー側（非公開）

8. 受け口・保存・保持は jamjam-server 側の ADR に置く（このリポジトリには書かない。`docs-spec/api/telemetry.md`
   同様に、送信先の事業者名・保存の詳細は公開しない）。エンドポイントのパス自体はクライアントのソースに現れるので公開情報として扱う。

## Consequences

- 利用者は、不具合に気づいた場でログを探さずに報告できるようになる。ログの中身は既存のマスクのまま送られるため、
  ADR-036 が既に受容しているリスク（ルーム ID・参加者の識別子が残る）はそのまま該当するが、公開の Issue に貼るより
  公開範囲は狭い
- `usage_reporting` がオフの利用者でも、この機能の利用（送信の有無・内容）自体は集計されない。送信の成否は
  画面にエラーとして表示するので、失敗を利用者が知らないまま「送った気になる」ことは無い
- サーバーが未対応（デプロイ前）の間は送信が失敗し、画面にエラーが出る。既存の「ログのフォルダを開く」で
  手動添付する手段は残る
