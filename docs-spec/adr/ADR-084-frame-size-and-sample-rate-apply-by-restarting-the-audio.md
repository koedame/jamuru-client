# ADR-084: バッファサイズとサンプルレートは、部屋にいるときは音声のセッションをやり直して反映する

## Status

Accepted。[ADR-043](./ADR-043-remote-operation-rpc.md) の「バッファサイズとサンプルレートは次の接続から効く」を置き換える。
ほかの設定（デバイス・チャンネル・送信チャンネル数・ジッタバッファの段数）が接続中に即時に効くことは変えない。

## Context

入室中にバッファサイズを 32 から 256 に変えても、画面右下の入出力の遅延の数値が変わらなかった。調べると、数値の表示が遅れていたのではなく、
変更が実際に効いていなかった。バッファサイズとサンプルレートは保存されるだけで、接続中のセッションには何も伝えられず、次に部屋へ入るまで
古い値で動いていた（`Plan.session` が空）。画面には選んだ値が出るので、効いたように見える。

フレームサイズとサンプルレートは音声エンジンの寿命のあいだ固定で、稼働中に変えるにはデバイスの再初期化がいる。
過去には、画面がストリーミングを止めて開き直したところ、新しいソケットの番号を相手が知らず音声が途切れた。

## Decision

- 接続中のセッションがあるときにバッファサイズかサンプルレートが変わったら（プリセットの切り替えでフレームサイズが変わる場合も）、
  保存したあとで**同じ部屋の中で音声のセッションをやり直す**（`Driver::restart_audio`）。セッションを止め、新しいソケットを
  結んで音声アドレスを部屋に公開し直し（`Audio::Advertise`）、デバイスを開き（`Audio::Open`）、公開済みの相手のアドレスへ
  接続し直す（`Audio::Start`）。相手は公開し直したアドレスを受けて、こちらへ繋ぎ直す。新しいセッションは保存した設定で始まる。
- シグナリングの接続と部屋は替えない。**部屋に入り直す案は採らない**: 部屋に自分しかいないとき、出た時点でサーバーが部屋を消し、
  入り直しは「Room not found」で失敗して部屋を失う（実機のベータで確かめた）。
- すでに使っている値を選び直したとき、部屋にいないとき、接続を取り戻している最中は、何もしない。次の入室・接続が保存した値で始まる。
- やり直しのあいだ（約 1 秒）は音が止まる。遅延の数値は新しいセッションの値になる。

## Consequences

- 入室中にバッファサイズを変えると、すぐ反映される代わりに、短い音の途切れが入る。部屋・参加者の一覧・招待コードは変わらない。
- 表示と実際の値が食い違わない。
- 表示名とサーバー URL は入室・接続のときに読まれ、変えても今の部屋には影響しない。これらは別の扱いである。

## Verification

- 要求: `REQ-GUI-024`
- `plan`（`src-tauri/src/settings.rs`）の単体テスト: 新しい値だけが新しいセッションを計画する
- `Roster`（`src/network/roster.rs`）の単体テスト: やり直しは新しい住所の公開・セッション・全員への接続を返す
- アプリ（`src-tauri/src/session/mod.rs`）のテスト: 入室中に変えると、同じ接続・同じ部屋のまま新しいフレームサイズで動き、住所が公開し直される。部屋の外では何もしない
