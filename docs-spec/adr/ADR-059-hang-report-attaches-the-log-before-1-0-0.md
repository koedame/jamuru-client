# ADR-059: 1.0.0 より前は、正常終了しなかった前回の起動の確認にも `jamjam.log` を添える

## Status

Accepted

## Context

[ADR-056](./ADR-056-hang-detection-and-reporting.md) は、`usage_reporting` がオフのまま前回の起動が正常終了しなかったとき、
次の起動でその場で聞いて 1 件だけ送れる仕組みを作ったが、送る内容は構造化された `hang` イベント（区間名・経過時間）だけにした。
[ADR-058](./ADR-058-report-a-problem.md) はその後、利用者が任意のタイミングで `jamjam.log` を添えて送れる「問題を報告」を別に作った。

1.0.0 より前は検証ユーザーだけがアプリを使う。固まりの再現・原因調査には、構造化イベントだけでは足りず `jamjam.log` の
実際の内容が要ることが多い。検証ユーザーが自分で「問題を報告」を押し直す一手間を省き、固まりに気づいた直後の確認 1 回で
ログも合わせて届くようにする。

## Decision

1. **1.0.0 より前のアプリ版に限り、ADR-056 の確認で「送る」を選んだとき、現在の `jamjam.log` も追加で送る。** 版は
   `app.package_info().version.major`（`src-tauri/src/usage.rs` の `attaches_log`）で見る。1.0.0 以上ではこの追加送信をしない。
2. **ログの送信は ADR-058「問題を報告」の送り先・本文の作り方をそのまま再利用する**（`report_problem::send_log_report`）。
   マスク・末尾 512 KiB への切り詰め・受け口（`POST /api/v1/problem-reports`）は新たに作らない。コメントには、どの区間で
   止まっていたかと今回の起動 ID を機械的に埋める（利用者の入力は求めない）。
3. **構造化された `hang` イベント（既存の `POST /api/v1/usage-logs` 経路）は変えない。** ログの追加送信はそれとは別に、
   同じ「送る」操作の結果として追加で行うだけである。
4. **ログの送信は失敗しても確認全体を失敗にしない。** 構造化イベントの送信（既存）と同じく、利用者に見えるのは
   「送った / 送らなかった」の 2 択だけで、ログ側の送信失敗は記録に残すだけにする（`tracing::warn!`）。
   ADR-058 の「問題を報告」自身は、利用者が明示的に押す操作なので送信の成否を画面に出すが、この確認は
   ADR-056 が決めた「利用者への確認は 1 回、送る/送らないの 2 択」という単純さを保つ。
5. **確認の説明文に、ログを添えることと、ログに何が入りうるか**（サーバーのアドレス・音声デバイスの名前・ルーム ID・
   他の参加者の識別子。ADR-036 の Consequences と同じ）**を書く**。1.0.0 以上の版では元の説明文（「音声・チャット・
   ルームの内容は含まれません」）に戻るよう、画面側もこの版の判定（`usage_previous_hang_attaches_log`）で分岐する。
6. **1.0.0 を出すときに見直す。** 伏せる項目を決めるとき、この追加送信をやめるだけで済むように、判定は
   1 箇所（`attaches_log`）にまとめてある。

## Reasons

- **新しい受け口を作らない。** ADR-058 が受け口・マスク・切り詰めを一度決めているので、同じ内容をもう一度違う形で
  送る経路を増やすと、伏せる項目を見直すときに 2 か所を直す必要が出る。
- **版の判定を 1 つの関数に閉じる。** 確認画面の文言も、送るかどうかも、同じ `attaches_log` /
  `usage_previous_hang_attaches_log` を見る。1.0.0 で挙動を変えるときに直す場所を 1 つにするため。

## Consequences

- 1.0.0 より前の検証ユーザーは、固まりの確認で「送る」を選ぶだけで `jamjam.log` も届く。ADR-058 の「問題を報告」を
  別途押す手間が要らない。
- 1.0.0 以上では、この確認は ADR-056 のときと同じ、構造化イベントだけの送信に戻る。
- ログの送信が失敗しても、構造化イベント（既存の経路）は届く。両方が失敗したときにサーバー側で気づく仕組みは
  [ADR-056](./ADR-056-hang-detection-and-reporting.md) の 3 節（版ごとに数える。非公開側）の対象。
