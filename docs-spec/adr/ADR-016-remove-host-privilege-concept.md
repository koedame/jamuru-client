# ADR-016: ルーム作成者特権（ホスト概念）の廃止

## Context

UI 用語集（[`docs-spec/ui/glossary.md`](../ui/glossary.md)。当時は `ui.pen`（Pencil デザインファイル）の `Doc/Glossary` にあった）に以下の決定が記録されている（2026-07-11付）:

> 「作成者」= ルームを作成した参加者。特権的な「ホスト」という概念は廃止し、他の参加者とは
> フラットな関係とする。

この決定はUIデザイン側では既に反映済みだったが、実装・仕様書側は未追従だった。追従にあたり
現状の実装を精査した結果、以下が判明した:

- シグナリングサーバーの `Room.host_id` は、**ルーム作成時に最初の参加者IDを記録するだけの観測用フィールド**
  であり、`JoinRoom`/`CreateRoom` を含むいかなる処理も `host_id` を使った権限分岐を行っていない。
- `ui/`（Tauri フロントエンド）・`src-tauri/` には「ホスト」概念のコード・文言が一切存在しない
  （リポジトリ全体を対象に `host`/`ホスト` を grep しても、`localhost` 等の無関係な一致以外は
  ゼロ件）。
- 唯一の例外は `docs-spec/api/signaling.md` 3.5節「ルーム終了（ホストのみ）」で、**未実装の計画**
  として `close_room()` をルーム作成者限定の操作にする案が書かれていた。

したがって本変更は挙動の変更を伴わない、安全なリネーム + 未実装の計画仕様の削除である。

## Decision

### 1. フィールド名の統一（Rust側）

シグナリングサーバーにおいて:

| 旧 | 新 |
|----|----|
| `Room.host_id` | `Room.creator_id` |

`CreateRoom` ハンドラ、関連テスト・テストヘルパー
（`make_test_room` 等）も同様にリネームする。挙動は変えない
（フィールド名のみの変更）。「作成者が退室しても再割当てを行わない」という既存の挙動
も維持する。

### 2. `docs-spec/api/signaling.md` 3.5節の削除

「ルーム終了（ホストのみ）」の計画を削除する。ルームを閉じるのはサーバーだけであり
（クライアントは `RoomClosed` を受けて切断する）、参加者自身によるホスト限定
操作という道具立ては本決定と矛盾するため追加しない。同節が参照していた計画中の `RoomDetails`
構造体の `host_id` フィールドも `creator_id` に修正する。

### 3. `docs-spec/ui/user-stories.md` / `docs-spec/behavior/connection.feature` の更新

「ホストとして参加」「ホストがセッションを終了する」等の特権的表現を、「作成者としてルームに
参加している」「参加者がルームを退室する（作成者を含め、退室してもルームは存続し他の参加者は
影響を受けない）」のようなフラットな表現に書き換える。作成者がセッションを終了する権限は
存在しないため、「セッション終了」シナリオ自体を削除し、代わりに「作成者を含む参加者が退室
してもルームは存続する」シナリオに置き換える。

## Consequences

### メリット

- UIデザイン（`.pen`）・用語集・仕様書・実装の一貫性が取れる。
- 将来「作成者に特権を持たせたい」という要求が出た場合も、本ADRが「意図的にフラット」と
  明記しているため、変更が必要な場合は新規ADRとして検討する起点になる。
