# ADR-074: 入力や出力のストリームがコールバックを呼ばなくなったら、気づいて開き直す

## Status

Accepted

## Context

Ubuntu 24.04 標準の PipeWire 1.0.5（`pipewire-alsa`）の上で、入室して 8 秒〜3 分のうちに、入力（または入力と出力の両方）が黙って止まった（beta.94、2 コアの VM、機器は null sink）。止まった状態は次のとおりだった。

1. `debug.perf` の `input_callback.count`（出力も止まった回は `output_callback.count`）が 0 になる。
2. 接続は `connected` のまま、`is_muted` は false、`device_problems` は空で、ログに入力のエラーの行は出ない。相手には自分の音が届かない。
3. 音のスレッド（`cpal_alsa_in`）は `poll` で待っていて、デッドロックではない。PipeWire の側ではノードが `running` のままで、xrun（`pw-top` の ERR）が数えられている。
4. 退室して入り直すと、ストリームが開き直されて戻る。

アプリは、ストリームのエラー（xrun・デバイスの切断）は受け取るが、「何も起きない」ことは知る手段が無かった。止まりは PipeWire の側の不具合かもしれないが、止まったことに気づいて開き直せば音が戻るので、アプリの側で気づけるようにする。

## Decision

1. **デバイスのコールバックは、毎回の呼び出しで `Heartbeat` に数える。** デバッグ用の測定（`perf`。既定では切れている）とは別に、常に数える。1 回の呼び出しに relaxed の足し算 1 回で、遅延には効かない。同じストリームを開き直しても、同じ数に数え続ける。
2. **セッションのスレッドが、毎周、数が動いたかを見る（`StallGuard`）。** 1 秒（`STALL_AFTER`）動かなければ止まったと見て、そのストリームを、デバイスを切り替えるときと同じ道（`DeviceSlot::switch`。別のスレッドで開く）で開き直す。見るのは入力と出力の別々で、同じ装置でも一方だけ止まることがある。
3. **開いているあいだと、開き終わった直後は、止まったと見なさない。** 開き直す前の数を時計の起点にすると、遅い開き（最大 8 秒）が止まりと誤判定される。また、呼び出しを待つスレッドが 1 秒より長く止まっていたとき（スリープ・プロセスの停止）は、ストリームがいつから止まっていたかが分からないので、そこから測り直す。
4. **開き直しても戻らないときは、3 回（`MAX_REOPENS`）で諦め、画面に出す。** 開けなかったときと同じ `device_problems` に `stalled` として入れ、「入力（出力）デバイスの音が止まりました。開き直しても戻りません。退室して入り直してください」と出す。開き直すたびに時計を測り直すので、3 回で約 3〜4 秒かかる。諦めたあとにコールバックが戻れば、知らせを消す。コールバックが戻ったときは、数え直しの回数も 0 に戻す。
5. **開けなかったデバイス・入力のないセッション・ASIO（Windows）は見ない。** 開けなかったときはすでに `device_problems` に出ている。ASIO は 1 つのセッションが入出力を持ち、別の道で開くので、この見張りの外にある。
6. **止まりを作る口をデバッグの版にだけ置く。** `jamjam::audio::fault::stall_streams`（`debug.stall_streams`）が、いま開いているストリームのコールバックを、エラーなしに止める（`open`）。`all` は、開き直したものも止める。フィーチャー `fault-injection` の外では、コードごと存在しない。
7. **開き直した回数を `debug.perf` に出す**（`input_reopens`・`output_reopens`）。

## Consequences

- REQ-AUD-128 の検証は、見張り（`StallGuard`）と、スロット（`DeviceSlot::watch`）の単体テスト、画面の知らせの UI テスト、`debug.stall_streams` を使った動作確認で行う。
- 止まりの原因（PipeWire の ALSA プラグインか、cpal の xrun の復帰か）は、この変更では直さない。止まったことに気づいて戻すのが目的で、止まりそのものが起きる頻度は変わらない。
- 開き直しには数十〜数百ミリ秒の無音が入る。止まったままよりよく、止まっていないストリームは開き直さない（コールバックが 1 秒に 1 回も無いのは、止まっている以外にない）。
- 負荷でオーディオのスレッドが 1 秒より長く動けなかったときも、開き直す。そのときの音はもともと途切れていて、開き直しで悪くならない。
