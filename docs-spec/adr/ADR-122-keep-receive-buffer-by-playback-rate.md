# ADR-122: 受信バッファの量を、再生の速さをごくわずかに変えて目標に保つ

## Status

Accepted

## Context

相手ごとの受信バッファ（`PlayoutBuffer`）の量は、聞こえる遅延そのものである（[ADR-028](./ADR-028-single-stage-playout.md)）。目標より多く溜まった分と少なくなった分は、次の経路で戻していた。

| 起きていること | 従来の戻し方 | 音への影響 |
|---|---|---|
| 相手の時計が自分より速い（遅い）。数十 ppm 〜数百 ppm のずれが一方向に溜まる | 窓（約 0.67 秒）の最小値が目標を 2 フレーム超えたら一度に捨てる（[ADR-048](./ADR-048-playout-gives-back-piled-up-frames.md)）。足りなくなったら空読みで無音を出し、遅れて 1 フレーム深くなる | 溜まるたびに飛ぶ（クリック）、足りなくなるたびに途切れる |
| 遅延の設定を下げた | 差の分を再生位置から一度に捨てる（[ADR-031](./ADR-031-live-playout-delay.md)） | 1 回の飛び |
| 遅延の設定を上げた | 次の読み出しで無音を入れて一度に溜める | 1 回の無音 |

時計のずれは止まらないので、飛びと途切れは一定の間隔で繰り返す。ずれが +500 ppm のとき、90 秒の再生で 33 回飛び、−500 ppm のときは 32 回途切れた（この ADR の統合テスト `tests/receive_rate_test.rs` の「従来」）。

時計のずれと遅延の設定の変更は、どちらも「バッファが持っている量が、目標の求める量とずれている」という同じ状態である。同じ 1 つの制御で戻せる。

## Decision

バッファの量と目標の差を、**再生の速さを ±1000 ppm の範囲でごくわずかに変える**ことで戻す。

### 1. 速さを決める（`src/audio/depth_rate.rs`）

読み出しのたびに保持数を取り、**0.5 秒の窓のあいだの最小値**を窓ごとに 1 回だけ求めて、速さを更新する（次の窓までは同じ速さを保つ）。最小値の系列を時定数 0.25 秒の指数移動平均で均し、「目標 + 1」（読んでいる最中のフレームを含む平常）との差から不感帯を引いた分を PI 制御に渡す。

平均の保持数ではなく窓の最小値を見るのは、回線のジッタで遅れて届くフレームのための余裕（保持数の底）を食わないため。平均を見る案は、3 フレームのジッタで途切れが出た（従来の「窓の最小値が目標を超えたら捨てる」と同じものを見る）。

| 項目 | 値 | 理由 |
|---|---|---|
| 不感帯 | 上 +1.0 フレーム・下 −0.25 フレーム。目標を動かした直後は ±0.2 | 位相の揺れで動かない。浅い側を狭くするのは、足りなくなる側が途切れるから |
| 固有角周波数 ω0 | 0.2 rad/s（ζ = 1） | 更新は 0.5 秒の窓ごとなので、ループの時定数（1/ω0 = 5 秒）を窓より十分長くとる |
| 積分項 | 時計のずれを学ぶ。±1000 ppm で止める | 学んだあとは不感帯の中でも補正し続ける |
| 補正の上限 | ±1000 ppm | 音程の変化は 1.7 セント。これを超えるずれは時計ではなく、従来の捨てる経路に任せる |

不感帯の下側は、統合テスト（−100 ppm で 90 秒。従来 5 回途切れる）で 0.5 フレームのままだと 87 秒の時点で 1 回空読みが出たので、0.25 フレームに狭めた（狭めたあとは 0 回）。

### 2. 速さを音に反映する（`src/audio/stretch.rs`）

`Stretcher` が、受信経路が読み出した直後のブロックに対して、1 サンプルフレームを取り除く（速く再生）か足す（遅く再生）。

- **1 回の伸び縮みは 1 サンプルフレーム**を **20 ms**（48 kHz で 960 サンプルフレーム）かけて行う。読み出し位置を出力に対して 1 サンプルフレームだけ先（遅れ）にずらし、等間隔に補間する。この間の速さのずれは 1/960、音程の変化は 1.8 セント以下で、補正の大きさにかかわらずこれを超えない
- 伸び縮みの間に補正が溜まる分は、次の伸び縮みで返す（溜められる量は 2 サンプルフレームまで）。1000 ppm は 20 ms あたり約 0.96 サンプルフレーム
- **伸び縮みの間は、音をそのまま通す**。フィルタも遅れも無い。補間は伸び縮みの中でだけ動く
- 補間は **16 点の窓付き sinc**（Kaiser 窓、β = 8）を 256 位相の表で引き、表の行の間は直線で補う。表は初回に作って `OnceLock` に持つ（読み出しの経路では確保しない）
- 伸び縮みの途中で音が切れた（無音・補間・読み出しの穴・再同期）ときは、伸び縮みを打ち切って次を最初からやり直す。打ち切るとき、読み込んだのにまだ出していない数サンプルフレーム（最大 15）は、切れたブロックの前に先に出す（捨てると、あとに続く音がその分だけ先に飛ぶ）。継ぎ目は従来の `Seam` が繋ぐ

補間の選び方（実測。1 kHz・10 kHz・15 kHz の正弦波を 1000 ppm で伸ばしたときの、理想の正弦波との差。レベルは入力に対する変化）:

| 補間 | 1 kHz | 10 kHz | 15 kHz | 18 kHz | 20 kHz |
|---|---|---|---|---|---|
| 直線 | 残差 −64 dB、レベル −0.01 dB | 残差 −22 dB、レベル −1.26 dB | 残差 −13 dB、レベル −2.88 dB | 残差 −8.6 dB、レベル −4.23 dB | 残差 −5.6 dB、レベル −5.28 dB |
| 16 点 sinc（β = 8） | 残差 −90 dB、レベル 0 dB | 残差 −86 dB、レベル 0 dB | 残差 −90 dB、レベル 0 dB | 残差 −42 dB、レベル −0.07 dB | 残差 −23 dB、レベル −0.59 dB |

直線補間は高域が落ち（10 kHz で −1.3 dB、15 kHz で −2.9 dB）、残差も大きい。3 次補間も試したが、10 kHz の残差が −29 dB に留まった。窓付き sinc は 15 kHz まで平坦で、残差は −85 dB 以下になる。計算量は、伸び縮みの最中でも 64 サンプルフレームの 1 回の呼び出しに 3.4 µs（デバイスの周期 1.33 ms の 0.26 %）、伸び縮みしていないときは 5 ns である。

β は 7・8・9 を同じ測定で比べた。β = 7 は 10 kHz の残差 −78 dB・18 kHz で −50 dB、β = 9 は 10 kHz で −97 dB・18 kHz で −38 dB。音楽の主な帯域（〜15 kHz）で残差が小さく、18 kHz 付近の落ち込みも小さい中間の 8 を採った。

### 3. 余りの扱い（`src/audio/playout.rs`）

速さを決める機能は、受信経路が `follow_depth_by_rate` で有効にする。有効なとき:

- **窓の最小値の余り**は、10 ms（480 サンプルフレーム）以下なら**捨てずに**速さで戻す。それを超える余りだけ、従来どおり一度に捨てる（上限 1000 ppm では 10 秒かからずに戻せる量を境にした）
- **遅延の設定を下げた**ときも、差が 10 ms 以内なら捨てずに速さで戻す（目標だけ動かし、不感帯を ±0.2 に狭める）。それを超える差は従来どおり一度に捨てる
- **遅延の設定を上げる**ときは従来どおり**一度だけ無音を入れる**。速さを下げて溜める案は、上げ幅が大きいと上限（1000 ppm）では間に合わず、遅延を上げる理由（回線が悪くなった）の最中に長く待たせるので採らない
- 空読み・再同期・`reset` のあとは、均した保持数を捨てて数え直す。学んだ時計のずれは `reset` まで持ち越す

## Consequences

### 良い影響

- 相手の時計のずれで、飛びも途切れも出ない（下の測定）
- 遅延の設定を小さく下げたとき、聞こえる飛びが無くなる
- 追従の速さは変えるが、音程の変化は常に 1.8 セント以下（測定で 2 セント以内）

### 悪い影響・残る作業

- 伸び縮みしている間、音は 1/960 だけ速い・遅い。1.8 セント以下で、聞き分けの閾値（5 セント）より小さい
- 伸び縮みの中だけ、高域（18 kHz 以上）がわずかに落ちる。15 kHz までは平坦
- 不感帯があるので、窓の最小値は目標 +1.0 〜 −0.25 フレームの範囲で揺れる。目標を 1 フレームに絞った回線で、浅い側の余裕は小さい
- 伸び縮みで再生が 1 サンプルフレームずつずれていくため、途切れた区間（空読み・無音）はデバイスの周期の境から数サンプルずれた位置に来る。周期の境に揃った途切れしか見えなかった従来の `cli_test` の「自分の音が聞こえない」の判定を、8 フレーム続いたときだけ聞こえたと数えるものに変えた（途切れの縁の 1〜2 フレームに出る漏れは、聞こえたと数えない）
- 時計のずれが 1000 ppm を超える相手は、補正しきれず従来の捨てる経路が働く
- 往復遅延（`roundtrip_total_ms`）と段数の変化を実機の 2 台で比べる測定は、この ADR の時点では実施していない。仮想時間の統合テストだけで確かめている（ベータ版の動作確認で測る）

### 検証

| 要求 | 検証 |
|------|------|
| REQ-LAT-134 | `src/audio/depth_rate.rs`（保持数が目標どおりなら速さを求めない・多ければ速く・少なければ遅く・上限を超えない・数百 ppm のずれを学ぶ）、`src/audio/stretch.rs`（1 回の伸び縮みで 1 サンプルフレーム・ランプがランプのまま・間はそのまま通る・切れたら打ち切る）、`src/audio/stream.rs`（大きな余りは捨て、小さな余りは速さで戻す）、`tests/receive_rate_test.rs`（相手の時計が ±100 / ±500 ppm ずれた 90 秒で、捨てた回数・途切れの回数・保持数の範囲を従来と比べる。正弦波と和音の音程が 2 セントを超えない。遅延の設定を下げたとき飛ばず途切れない。ジッタのある回線で従来より悪くならない） |

統合テストの結果（90 秒、仮想時間。従来 → 今回）:

| ずれ | 一度に捨てた回数 | 途切れ（空読み） | 保持数の範囲 |
|---|---|---|---|
| +500 ppm | 33 → 0 | 0 → 0 | 1..3 → 0..2 |
| +100 ppm | 7 → 0 | 0 → 0 | 1..3 → 0..2 |
| −100 ppm | 0 → 0 | 5 → 0 | 0..0 → 0..2 |
| −500 ppm | 0 → 0 | 32 → 0 | 0..0 → 0..2 |

遅延の設定を 6 から 3 に下げたとき、一度に捨てた回数は 5 → 0、途切れは 0 → 0。ジッタのある回線（フレームが最大 0.5〜1 フレーム遅れて届く）では、+100 ppm で捨てた 8 → 0、+300 ppm で 22 → 0、−100 ppm の途切れ 4 → 0、−300 ppm で 17 → 0（保持数の底を従来と同じ窓の最小値で見ているので、悪くならない）。

音程の最大のずれは 1.58〜1.71 セント（1 kHz の正弦波と和音。50 ms ごと、制限 2 セント）。学んだ速さの末尾は真のずれに近い（+500 → 520、−500 → −548、+100 → 94、−100 → −123）。
