# ADR-079: 暗号化したリンクでは、公開されていないアドレスから届いたパケットの送り元へ送り先を移す

## Status

Accepted

## Context

回線の切り替えや NAT の付け替えで、相手の外から見えるポートやアドレスが、シグナリングで公開されたものから変わることがある。
こちらには相手の音が届くが、送り先は公開されたアドレスのまま動かず、相手は何も聞こえないまま `failed` で止まる
（接続 2 つを、ポートを付け替える中継越しにつないで再現した。`tests/address_change_test.rs`）。

[ADR-051](./ADR-051-route-follows-the-peers-answers.md) の送り先の追従（`Route::follow`）は、移る先を接続の確認のときに相手が出した候補
（`others`）に載っているアドレスだけに限っていた。暗号化が確立したあとは、知らないアドレスからの音声・keep-alive も復号されて届く
（`route.knows` で捨てるのは制御パケットと、暗号化が決まる前だけ）ので、相手のパケットと分かっているのに、送り先は動かなかった。

[ADR-068](./ADR-068-follow-the-peer-after-rejoin.md) の 5 は、原因を問わず効く手段として、諦めたら入り直す対処を入れた。入り直すと、
部屋に出入りが見え、数秒音が途切れる。

## Decision

暗号化が確立したリンク（`LinkSecurity::Encrypted`）で、復号と重複の検査を通ったパケットが知らないアドレスから届き、
送り先宛の ping への返事が `answer_wait` のあいだ無いときは、そのアドレスを相手のアドレスに加え（`Route::learn_roamed`）、
既存の `Route::follow` で送り先を移す。

- 移す条件に「返事が無いこと」を残すので、返事のある経路が生きているあいだは、知らないアドレスのパケットで送り先は動かない。
- 暗号化していないリンク（鍵の合意前・暗号化しない旧版）では移さない。送り元のアドレスは誰でも偽れるため。
- 暗号化したリンクで検査を通るパケットは、鍵を持つ相手だけが作れる。送り元のアドレスは認証の対象外だが、第三者が相手のパケットを
  別のアドレスから複製して送っても、重複の検査（`window.is_new`）で、先に届いた本物のあとのものは捨てられる。第三者が本物より先に
  届けられるのは、経路の途中にいる攻撃者だけで、そのときは経路ごと遮断できるので、送り先を移すことで得るものは増えない
  （WireGuard の送り先の追従と同じ考え方）。
- 入り直す対処（ADR-068 の 5）は残す。原因を問わず効く手段であり、移す方で足りないとき（相手の新しいアドレスへこちらから送れない等）の備え。

## Consequences

- 相手のポートが断のあとに変わっても、入り直さずに、数秒で双方向が戻る（再現テスト: 変更前は片方が 0 パケット・`Failed` のまま）。
- 経路の変更に関わるのは、返事が無いまま届いたパケットのときだけ。通常の音声の経路は変えていない。
- 実機の NAT では確かめていない。ループバックの中継で同じ状況を作ったもの。
