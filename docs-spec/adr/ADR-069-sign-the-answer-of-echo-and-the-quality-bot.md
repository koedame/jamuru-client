# ADR-069: echo と音質チェックのボットは、受け取ったアプリの一時鍵あてに署名して答える

## Status

Accepted

## Context

[ADR-067](./ADR-067-check-the-peer-in-the-key-exchange.md) で、ルームの相手とは `link_key` で鍵交換に署名し、署名の合わない鍵交換を受け付けないようにした。
echo と音質チェックのボットは `link_key` を知らせなかったので、アプリはこの 2 つとの通信を、暗号化はするが相手が本人かは確かめないままにしていた。
同じ LAN や経路上で書き換えられる者は、アプリと echo の間に入って、echo に返す音声を聞けた。

ADR-067 の署名は、宛先の `link_key` を対象に含める。echo とボットは 1 つの UDP ソケットで多数のアプリと話し、相手を送信元の住所で見分けている。
住所からアプリの `link_key` を引くには、アプリが知らせた住所に載っている必要があるが、NAT の向こうでは知らせた住所と実際の送信元がずれ、
LAN から直接来る相手は載っていない。引けない相手に署名なしで答えると、`link_key` を知るアプリは署名の無い鍵交換を受け付けないので繋がらない。

「引けた相手には署名し、引けない相手には署名なしで答える」案は、アプリに「この相手の署名なしの鍵交換も受け付ける」という印を持たせることになる。
経路上の者は echo の署名つきの鍵交換を、署名なしの自分の鍵に差し替えるだけでアプリに受け付けさせられるので、確かめたことにならない。

## Decision

1. **echo とボットは、入室のときに自分の `link_key` を知らせる。** 起動のたびに `LinkIdentity` を作る。
2. **署名の対象に、宛先の `link_key` の代わりに「答える相手の一時鍵」を使えるようにする。** 署名の対象は
   `"jamjam-link-key-exchange-answer-v1:"` に、送り手の `link_key`・答える相手の一時鍵・送り手の一時鍵を続けたもの（ADR-067 とは別の接頭辞）。
   echo とボットは、アプリの鍵交換を受け取って初めて答えを作る（`SecureLink::answering`）。アプリが誰かは確かめない。
3. **アプリは、相手の `link_key` で署名された鍵交換を、署名の対象が自分の `link_key` でも自分の一時鍵でも受け付ける。** 署名の無いものは、どの相手のものも受け付けない。
   ADR-067 の「相手の鍵が分かっているリンクは署名なしに落ちない」は変わらない。印は増えない。
4. **署名の無い鍵交換を送ってくる相手には、署名の無い鍵交換で答える。** 署名に対応する前の版のアプリと、平文で送る相手（ADR-064）は、これまでどおり繋がる。
5. **確かめ方は、割り込む中継。** `jamjam-server` の `tests/echo_encryption_test.rs` に、echo との間で鍵交換を差し替える中継を置く。

### 安全であることの根拠

アプリが受け付けるのは、echo の `link_key` の秘密鍵で作った署名だけで、その対象にはアプリがそのリンクのために作った一時鍵が入る。
echo は、どの相手に対しても、署名する「送り手の一時鍵」に**自分の**一時鍵を使う。割り込む者が echo に鍵交換を送って答えを得ても、
その答えに載っているのは echo の一時鍵で、割り込む者はその秘密を持たないので、アプリとの間で鍵を共有できない。
アプリの一時鍵を入れて署名した答えは、そのアプリのリンクにしか通らない（別のアプリへ使い回すと受け付けない）。

### 選ばなかったもの

- **引けた相手とは署名つき、引けない相手とは署名なし（案 B）**: 上のとおり、署名なしを受け付ける入口が割り込みの道になり、確かめたことにならない。
- **引けなかった相手を断る（案 C）**: NAT の向こうのアプリが echo に繋がらなくなる。
- **アプリが自分の `link_key` を鍵交換に載せ、echo がそれあてに署名する**: アプリの鍵交換の形式を変えるので、配布中の版が相手の形式を読めない期間ができる。
  一時鍵あてにすれば、アプリが送る鍵交換は ADR-067 のままで済む。

## Consequences

- **echo とボットとの通信も、経路上の第三者に対して相手が本人であることを確かめられる**。確かめない接続は、古い版の相手とサーバーを使わない直接接続だけになる。
- **`link_key` を使う版のアプリ（ADR-067 を含むベータ版）のうち、この変更を含まない版は、echo とボットに繋がらなくなる。**
  echo が知らせる `link_key` を見て署名を確かめるが、署名の対象が自分の `link_key` ではないため。署名に対応する前の版は影響を受けない。
- echo とボットを信じる前提は、シグナリングのサーバーを信じる前提と同じ（`link_key` はそこから届く）。
- 入室から音が出るまでの時間は、echo 側の署名 1 回と、アプリ側の検証が 1〜2 回の分だけ延びる。
