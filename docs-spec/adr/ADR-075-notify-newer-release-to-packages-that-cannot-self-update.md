# ADR-075: 自分で入れ替えられない配布形態にも、新しい版が出たことを画面で知らせる

## Status

Accepted。[ADR-041](./ADR-041-self-update.md) の 7 節「deb と MSI は更新を試みない」に、知らせを足す（入れ替えはしない決めは変えない）。

## Context

Linux の `.deb` と Windows の `.msi` は、自分で入れ替えられない（ADR-041 7 節）。このため、起動の 20 秒後に `Not checking for an update: this package cannot replace itself` をログに 1 行出すだけで、更新情報の取得もしなかった。**新しい版が出ても、画面には何も出ない。**

1.0.0 までは、古い版と新しい版がつながらなくなる変更を入れてよい決まりである。`.deb` や `.msi` で入れたテストユーザーは、ある日つながらなくなっても、理由が新しい版が出たことだと分からない。導入の説明は自動更新に対応するものを挙げているだけで、`.deb` が対応しないことはその裏返しでしか読めなかった。

Ubuntu 24.04 の実機で確かめた事実: AppImage は 1 つ前の版で起動すると、20 秒後に新しい版を見つけて入れ替わり、新しい版でつながった。`.deb` は新しい版を見つけることもしなかった。

## Decision

1. **自分で入れ替えられない配布形態は、新しい版が出ていないかだけを、自動更新と同じ時期・同じ頻度（起動の 20 秒後と 6 時間おき）で確かめる。** ダウンロードも入れ替えもしない。`auto_update = false` のときは確かめない（確認も適用もしない、と同じ）。開発ビルドは確かめない。
   - 却下: 導入の説明に「`.deb` は自分で入れ直す」と書くだけにする。書いてあっても、入れてから読み返す人は少ない。つながらなくなった理由を、画面は教えられない。
   - 却下: そのままにする。上の事実のとおり、気づく手段が無い。
2. **見つけた版は、画面の一番上に 1 行で出す**（「新しい版 X が出ています。入れ直してください」）。接続前の画面にも、入室後の画面にも出す。古い版は、部屋に入るところまで行けないことがあるので、接続前の画面に出ることが要る。手伝いの画面（ADR-044）には出さない。手伝う人が入れ替える物ではない。出すだけで、閉じるボタンは付けない（入れ直せば消える）。
3. **画面が受け取るのは、版の文字列だけ。** 読む口（`update_notice_get`）は、手伝いの口には開けない。入れ替え・ダウンロードを促す口は、これまでどおり無い。ADR-041 の「更新は webview から動かさない」は保つ。
4. **更新情報の Linux の項目は、AppImage のものを読む。** 更新情報（`latest.json`）は、版を全体で 1 つだけ持ち、Linux の項目は AppImage にしかない（`scripts/make-update-manifest.sh`）。`.deb` の項目を足さないのは、`.deb` には署名つきの成果物が無いからである。知らせるのは版の数字だけなので、AppImage の項目で版を読めば足りる。実際のベータ版の更新情報に対して、`.deb` の項目では `TargetNotFound`、AppImage の項目では版が返ることを確かめた。Windows の `.msi` の項目は、更新情報にもともとある。

## Consequences

- `.deb` と `.msi` のアプリも、起動のたびと 6 時間おきに GitHub へ接続する（更新情報の取得だけ。送るのはアプリの版と OS の種類）。プライバシーの文書の「自動更新のための通信」に、すでにあるとおり。
- 知らせは版の違いしか見ない。つながらなくなる変更が入った版かどうかは区別しない。
- 画面の 1 行は、新しい版を入れるまで消えない。入れ直す人にとってだけ意味があるので、`auto_update = false` にすれば出ない。
