# ADR-062: 「最近の接続」（入ったルームの履歴）を、画面・呼び出し・設定ファイルの項目ごと無くす

## Status

Accepted

## Context

接続前の画面には「最近の接続」があった。入ったルームのコードを最大 10 件、日時つきで並べ、選ぶと参加コードの欄に入り、
✕ で 1 件ずつ消せた。uchida から、この項目をアプリから削除してほしいと依頼があった。

履歴は画面の一部というだけでなく、設定ファイルの `connection_history` と、それを読み書きする 5 つの呼び出し
（`config_get_connection_history` ほか）、ルームに入るたびに追記する処理、利用状況から外す項目（REQ-TEL-004）にまでつながっていた。

## Decision

1. **画面から「最近の接続」を外し、それを支えていた部品ごと消す。** 接続画面の一覧、単独の `ConnectionHistory` 部品、
   日付の書式、翻訳文言（`connectionHistory.*`）が対象。
2. **履歴の呼び出し 5 つ、ルームに入ったときの追記、設定ファイルの `connection_history` も消す。**
   画面だけ消して保存を続けると、利用者から見えず消すこともできない履歴が設定ファイルに溜まり続ける。
   ルームのコードは人を特定しうる情報なので、見えない場所に残さない。
3. **利用状況から外す項目は 4 つから 3 つになる。** `connection_history` が設定ファイルから無くなるので、外す一覧からも消す
   （REQ-TEL-004）。手伝いの口の「できない操作」からも、履歴の呼び出しが無くなる（REQ-RMT-025）。
4. **既に履歴が入っている設定ファイルは読み込み側で無視する。** 読み込みは未知の項目を拒まないので、移行の処理は要らない。
   古い `connection_history` は、次に設定を保存したときに自然に消える。
5. **却下: 画面だけ消す。** 上の 2 のとおり、見えない履歴が残る。
6. **却下: 履歴を残して画面の設定で隠せるようにする。** 依頼は削除であり、使われない設定項目が増えるだけになる。

## Consequences

- 直前に入ったルームへ戻るには、招待コードをもう一度入力するか、共有されたリンクを開く。
- 過去に保存された履歴は、設定を保存し直すまで設定ファイルに残る。読み出す経路が無いので、アプリの挙動には影響しない。
- 履歴を復活させる場合は、保存する項目・消す操作・利用状況から外す設定を、ここで消したものと同じ組で作り直す。
