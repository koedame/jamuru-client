# ADR-036: 公開ビルドでも診断ログファイル `jamjam.log` を書く

## Status

Accepted

## Context

`brew` で入れた `v0.1.0-rc.1` が「画面は出るが、どのボタンも反応しない」状態になった。原因を外から知る手段が無かった。

- 公開ビルドにはコンソールも開発者ツールも無い。
- `src-tauri` の `tracing`（接続・ストリーム開始・警告）は購読者が付いておらず、E2E ハーネスの標準エラー出力（ADR-025 の `init_tracing`）以外では**どこにも出ていなかった**。
- 画面側の `console.error` は開発者ツールの中にしか出ない。
- Tauri は、権限（capability）が無い呼び出しを Rust 側のログに残さない。webview の Promise が拒否されるだけである。

不具合のたびに推測で当たりを付ける代わりに、利用者にファイルを 1 つ貼ってもらえば足りる状態にする。

## Decision

1. **どのビルドでも `jamjam.log` を OS 標準のログ置き場に書く。** tauri-plugin-log の `LogDir` ターゲットを使う（macOS `~/Library/Logs/me.koeda.jamjam/`、Linux `~/.local/share/me.koeda.jamjam/logs/`、Windows `%LOCALAPPDATA%\me.koeda.jamjam\logs`）。OS 標準の置き場とサイズによるローテーションが既製で揃うため。
   - 却下: `tracing-appender`。ローテーションが時間単位のみでサイズ上限を持てない。
   - 却下: 自前のファイル書き出し。上の 2 つを作り直すことになる。
2. **`tracing` のイベントを `log` に流す。** `tracing` の `log-always` feature を有効にし、`src-tauri` とコアライブラリ（`jamjam`）の `tracing` イベントをそのまま同じファイルに書く。`e2e-control` 用の `init_tracing`（ADR-025）は廃止し、標準エラー出力ターゲットに置き換える（debug ビルドと `e2e-control` ビルドのみ。購読者が 2 系統あると `log` の出力先が衝突するため、経路を 1 本にした）。
3. **ロガーは、状態を作る前に入れる。** 状態（`SignalingState` など）を作るときに出るログ（読めない設定、捨てた端末識別子）は起動時のログの中でも重要である。そのため `tauri::Builder::build` でアプリを作ってロガーを入れ、その後に `App::manage` で状態を登録し、`run` でウィンドウを作る。`Builder::manage` のままだとロガーより先に状態が作られる。
   - ロガーは tauri-plugin-log そのものではなく、`Builder::split` で得たロガーを入れる自前のプラグイン（`jamjam-log`）で入れる。プラグイン標準の `build()` はログのフォルダを作れないと**アプリの起動ごと失敗させる**。診断機能が起動を止めてはならない。ログを書けないときは標準エラー出力に一言出して、ログ無しで動く。
4. **画面側の出力は、アプリのコマンド `log_frontend` でファイルに送る。** tauri-plugin-log の JavaScript 側コマンドは capability を要する。ログは、capability の不備を調べるときにこそ動いていなければならないので、権限に依存しないアプリのコマンドを使う。
   - 送るもの: `console.log/info/warn/error/debug`、捕捉されなかったエラー、未処理の Promise 拒否。
   - 失敗したコマンドの名前とエラーは、UI の `invoke` ラッパー（`ui/src/lib/invoke.ts`）が記録する。成功は debug。**引数は書かない**（部屋のパスワードとチャット本文が入る）。Tauri は webview の `__TAURI_INTERNALS__.invoke` を読み取り専用にしているので、その場で差し替える方法は取れない。
   - 行は 1 本ずつ順に送る（`log_frontend` は非同期コマンドで、同時に送ると実行順が入れ替わりうるため）。同期コマンドにしないのは、メインスレッドで動くコマンド（デバイスの列挙は数十 ms かかる）の後ろに、画面が書く行が並んでしまうため。
   - 100〜500ms ごとのポーリング（`streaming_status` など）が失敗し続けても、同じ行は 10 秒に 3 回まで。残りは数えて次の行に添える。ローテーションで大事な履歴を押し出さないため。制限が効くのは内容が同じ行だけで、内容が毎回変わる行は制限しない。
5. **レベル。** 自分のクレート（`jamjam`、`jamjam_app_lib`、画面側 `webview`）は debug、依存クレートは info。環境変数 `JAMJAM_LOG` で上書きできる。`trace` のように水準だけ書くと全対象に、`jamjam=trace,tao=debug` のように書くと対象ごとに効く。水準だけの指定と対象ごとの指定が並ぶときは、書く順に依らず対象ごとの指定が勝つ（`jamjam=trace,info` と `info,jamjam=trace` は同じ）。解釈できない部分は無視し、起動時の 1 行目付近に警告として残す。
6. **サイズ。** 1 ファイル 5 MiB。現在の `jamjam.log` と古い 2 世代（`jamjam_<日時>.log`）を残し、合計 15 MiB を超えない。起動のたびに新しいファイルは作らず、同じファイルに追記する（区切りは起動時の `starting` 行）。
   - Rust 側は、同じ呼び出し箇所（`tracing` マクロの書かれた行）から書くのを 10 秒に 5 件までにし、残りは数えて次の行に添える。パケットごとに失敗する `warn!`（復号の失敗など）が、1 分足らずでファイルを埋めて履歴を押し出すのを防ぐ。パケットごとに出る FEC 復元の行は `debug` から `trace` に下げた。
7. **秘匿情報。**
   - 書く場所（`log_frontend`）で `password` / `passwd` / `secret` / `token` を含む名前の `名前: 値` と `名前=値` の値を `***` にする。引用符付きの値と多バイト文字は多めに伏せる側に倒す。`password hunter2` のような地の文は判定しない（文中の「password」の次の語を毎回伏せると、このファイルが残したいメッセージまで消える）。デスクトップ版は今のところ部屋のパスワードを入力する手段を持たず、これはパスワードを扱うようになったときのための歯止めである。
   - 起動時の設定の要約は、名前を挙げた項目だけを書く（設定の `Debug` 出力は使わない。設定に項目が増えても、誰かが判断するまでファイルには出ない）。サーバー URL の認証情報は除く。
   - 端末識別子はログに書かない（REQ-GUI-002。以前の `Generated device identity <id>` を、識別子を含まない文言にした）。
   - 招待リンクは受け取ったことだけを書き、招待コードは書かない。参加時にユーザーが入力した部屋の指定（招待コードのことが多い）も Rust 側のログには書かない（サーバーが返した部屋 ID は書く）。
   - 画面側の 1 行は 8 KiB で切る。
8. **設定の Diagnostics タブに「ログのフォルダを開く」を置く。** OS のファイルマネージャを起動するコマンド `log_open_dir` を、shell プラグインを経由せずに自前で持つ（同じ理由で capability に依存しない）。開けなかったときはフォルダの場所を含むエラーを返す。
9. **パニックも記録する。** コマンドやタスクの中のパニックは、インストール版では誰にも見えない標準エラー出力にしか出ないため、パニックフックで `error` として書く。

## Consequences

- 不具合報告に `jamjam.log` 1 つを添えれば、接続の成否と所要時間、失敗したコマンドとエラー、画面の状態遷移（`[session] connecting_server -> error: ...`）、オーディオの開始と失敗が読める。
- ファイルには、サーバー URL・オーディオデバイス名・ルーム ID・他の参加者の識別子・ルーム名を含みうる。パスワード・招待コード・端末識別子は書かない。共有する前提で読み返す。
- `invoke` ラッパーを通らない呼び出し（イベントの購読やウィンドウ操作など、`@tauri-apps/api` が内部で呼ぶ `plugin:*` コマンド）の失敗は、`console` に出たものか未処理の Promise 拒否としてだけ残る。capability の拒否はメッセージにコマンド名が入る。
- webview が読み込めない（画面が真っ白）場合、ファイルには Rust 側の行だけが残る。画面側の行が無いこと自体が手掛かりになる。
- 起動時の状態作りがロガーの後ろに移ったので、`tauri.conf.json` で作られるウィンドウが状態より先にコマンドを呼ぶことはない（ウィンドウは `run` で作られる）。
