# トラブルシューティング

jamjamで問題が発生した場合の解決方法をまとめています。

## 接続の問題

### サーバーに接続できない

**症状**: 「サーバーに接続できません」エラーが表示される

**原因と解決策**:
1. **インターネット接続を確認**
   - 他のウェブサイトにアクセスできるか確認
   - Wi-Fiまたは有線接続が安定しているか確認

2. **シグナリングサーバーURLを確認**
   - 設定ファイル `config.toml` の `server_url` で接続先を変えている場合は、その URL が正しいか確認

3. **ファイアウォール設定**
   - jamjamがネットワークアクセスを許可されているか確認
   - Windows: 「Windows セキュリティ」→「ファイアウォールとネットワーク保護」
   - macOS: 「システム設定」→「ネットワーク」→「ファイアウォール」

### ルームが見つからない

**症状**: 「Room not found」エラーが表示される

**解決策**:
1. 招待コードが正しく入力されているか確認（9文字の英数字、大文字）
2. ルームがまだ存在しているか確認（ホストが退出するとルームは削除される）
3. コードを再度ホストに確認する

### 接続がタイムアウトする

**症状**: 接続が完了せず、タイムアウトする

**原因と解決策**:
1. **NATの問題**
   - 対称NAT（Symmetric NAT）環境では直接接続が難しい場合がある
   - VPNを使用している場合は無効にして試す

2. **ネットワーク遅延**
   - 安定した回線を使用する
   - 可能であれば有線接続を使用

## 音声の問題

### 音声が聞こえない

**症状**: 接続は成功したが、相手の音声が聞こえない

**解決策**:
1. **出力デバイスを確認**
   - 設定画面で正しい出力デバイスが選択されているか確認
   - システムの音量がミュートになっていないか確認

2. **入力デバイスを確認（相手側）**
   - 相手のマイクが正しく設定されているか確認
   - 入力レベルメーターが反応しているか確認

3. **ミュート状態を確認**
   - マイクミュートボタンがオンになっていないか確認

### 音声が途切れる・ノイズが入る

**症状**: 音声が断続的に途切れる、またはノイズが混入する

**解決策**:
1. **プリセットを調整**
   - 「balanced」または「high-quality」プリセットに変更
   - ネットワーク状態が悪い場合、より保守的な設定を使用

2. **バッファサイズを増やす**
   - 設定画面でオーディオバッファサイズを増やす
   - 128 → 256 または 256 → 512 に調整

3. **ネットワーク帯域を確認**
   - 他の帯域を消費するアプリ（動画ストリーミング等）を停止
   - 可能であれば有線接続を使用

### 遅延が大きい

**症状**: 音声の遅延が気になる

**解決策**:
1. **プリセットを変更**
   - 「zero-latency」または「ultra-low-latency」を試す
   - 推奨設定が表示されている場合はそれに従う

2. **バッファサイズを減らす**
   - 設定画面でオーディオバッファサイズを減らす
   - 注意: 小さすぎると音声が途切れる場合がある

3. **ネットワーク品質を確認**
   - RTT（往復遅延時間）が低いほど低遅延になる
   - 日本国内光回線で10-25ms程度が目安

## アプリケーションの問題

### アプリが起動しない

**Windows**:
1. Visual C++ 再頒布可能パッケージがインストールされているか確認
2. .NET Framework が最新か確認
3. 管理者として実行を試す

**macOS**:
1. 「システム設定」→「プライバシーとセキュリティ」で許可
2. 「このまま開く」を選択

**Linux**:
1. 必要なライブラリがインストールされているか確認:
   ```bash
   sudo apt-get install libasound2 libssl3 libwebkit2gtk-4.1-0
   ```
2. AppImageの場合、実行権限を付与:
   ```bash
   chmod +x jamjam.AppImage
   ```

### 設定が保存されない

**症状**: アプリを再起動すると設定がリセットされる

**解決策**:
1. 設定ファイルの場所を確認:
   - Linux: `~/.config/jamjam/config.toml`
   - macOS: `~/Library/Application Support/jamjam/config.toml`
   - Windows: `%APPDATA%\jamjam\config.toml`

2. ディレクトリの書き込み権限を確認

### クラッシュする

**症状**: 使用中にアプリが突然終了する

**解決策**:
1. アプリを最新版に更新
2. 設定ファイルを削除して初期化:
   ```bash
   # Linux/macOS
   rm -rf ~/.config/jamjam/

   # Windows (PowerShell)
   Remove-Item -Recurse $env:APPDATA\jamjam
   ```

## テストユーザー向け追加情報

### ログの取得

jamjam は動作の記録を `jamjam.log` に書き続けます。ボタンが反応しない、接続できないなど、画面からは原因が分からないときは、このファイルを問題報告に添えてください。

1. アプリを起動
2. 問題を再現
3. 設定画面の「診断」タブにある「ログのフォルダを開く」を押す。フォルダが開かない環境では、次の場所を直接開く:
   - Linux: `~/.local/share/me.koeda.jamjam/logs/`
   - macOS: `~/Library/Logs/me.koeda.jamjam/`
   - Windows: `%LOCALAPPDATA%\me.koeda.jamjam\logs\`
4. `jamjam.log` を添付する

書かれる内容: アプリのバージョン・OS・設定（サーバーURL、選んだオーディオデバイス、バッファサイズ）、サーバーへの接続と部屋の作成・参加・退出、オーディオの開始と停止、失敗したコマンドとそのエラー、画面側の状態の遷移とエラー。部屋のパスワードと、招待リンクの招待コードは書かれません。

IP アドレスとオーディオデバイスの ID は既定でマスクされます（例: `203.0.113.x`、デバイス名のみ表示してシリアル番号は伏せる）。NAT やネットワーク経路の問題を自分で調べたいときは、環境変数 `JAMJAM_LOG_REDACT=off` を付けて起動するとマスクされていない値が書かれます。

`jamjam.log` が 5 MB を超えると `jamjam_<日時>.log` に改名され、新しい `jamjam.log` に書き始めます。残るのは現在のファイルと古い 2 世代までです。詳しく見たいときは、環境変数 `JAMJAM_LOG` で出力レベルを変えて起動できます（例: `JAMJAM_LOG=trace`。`jamjam=trace,info` のように対象ごとの指定も可）。

### 問題報告

問題を報告する際は以下の情報を含めてください:

1. **環境情報**
   - OS（Windows/macOS/Linux）とバージョン
   - jamjamのバージョン
   - 使用しているオーディオデバイス

2. **問題の詳細**
   - 何をしたか（手順）
   - 期待した動作
   - 実際の動作
   - エラーメッセージ（ある場合）

3. **ログファイル**（`jamjam.log`。取得方法は上の「ログの取得」）
